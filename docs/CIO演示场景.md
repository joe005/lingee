# CIO 演示场景：工单管理系统开发

CIO 在「管理」里一屏掌握所有在跑项目；以工单管理系统为例，项目负责人立项、拉成员、建研发任务，研发侧由智能体团队按阶段交付，成员审核；任务完成后状态、代码合并和进度自动回到管理项目详情。

| | 说明 |
| --- | --- |
| 汇报页 | `deck/汇报v2/灵基汇报-CIO与Build-v2`（HTML / PPT）第 1–2 页：三项核心议题（开发效率 / 过程可控 / 价值可见）+ 视频 Demo |
| 一句话客户价值 | 项目风险当天可见，系统交付周期从 12 周缩短到 4 周 |
| 账号 | 吴宏超（项目负责人，管理）；需求、开发、测试（角色账号，开发板块处理各自阶段，视频剪掉换账号登录） |
| 管理项目 | 新建「工单管理系统」：模板「通用开发」，Git `https://gitlab.kingdee.com`，基准分支 main，交付智能体团队「通用应用开发智能体团队」 |
| 研发任务 | 「工单提交」，执行计划保留 需求分析（需求）→ 开发实现（开发）→ 测试验证（测试） |
| 开发实现产物 | 网站预览：工单管理系统（`src/artifacts/helpdesk-app.html`） |

## 视频（约 79 秒，`deck/汇报v2/灵基CIO-产品Demo.mp4`，2560×1440，无封面、无字幕）

画面为原型无头录制，没有浏览器框；换账号登录、等待智能体生成的过程剪掉。

| # | 画面与操作 | 逐字稿 |
| --- | --- | --- |
| 1 | 吴宏超 → 管理 → 项目全景 | 打开灵基 Manage，所有在跑项目一屏呈现。 |
| 2 | 依次指向带风险、待决策标签的项目卡片 | 每张卡片都写着目标、进度、风险与待决策。哪个项目落后、哪里有风险，一目了然，不必等例会汇报。 |
| 3 | 新建项目 → 通用开发 → 填名称、目标、Git → 创建，新卡片出现在全景里 | 以工单管理系统为例，项目负责人在 Manage 中立项。项目一创建，就出现在 CIO 的项目全景里。 |
| 4 | 打开项目 → 项目成员 → 加入需求、开发、测试并设置角色 → 保存 | 需求、开发、测试成员加入项目。从立项那一刻起，项目就纳入统一管理，进度和风险随时可查。 |
| 5 | 新建任务「工单提交」→ 执行计划删去架构设计、智能体开发，三个阶段分别指定执行人 | 项目计划拆成具体任务。新建任务时，智能体团队自动带出执行阶段，每个阶段都有明确的负责人。 |
| 6 | 保存并分配 → 打开任务详情，看到执行阶段与代码分支 | 计划一旦确定，就直接驱动研发执行。计划与执行使用同一份数据，不再依赖人工同步。 |
| 7 | 需求 → 需求文档；开发 → 网站预览（工单管理系统）；测试 → 测试报告 → 完成 | 研发侧由智能体团队按阶段交付需求文档、可运行的系统和测试报告，成员审核把关，CIO 不必逐个跟进细节。 |
| 8 | 回到吴宏超的管理项目详情，任务状态「已完成」 | 回到项目详情，任务已自动标记为完成。 |
| 9 | 打开任务详情：代码分支已合并到 main，进展记录 | 阶段结论、代码合并和每一次状态变化都有记录，全程可追溯。 |
| 10 | 关闭详情，项目概览进度 100% | 项目进度同步更新到 100%。进度看得清，风险早发现，CIO 决策更高效。 |
| 11 | 停在项目详情 | 人与智能体协同交付，让 IT 交付跟上业务。 |

## 演讲备注（视频页）

这段 Demo 对应三项议题。过程可控：CIO 在 Manage 中一屏掌握所有项目的目标、进度、风险与待决策，立项、拉成员、建任务都在同一处完成。开发效率：新建研发任务时智能体团队自动带出执行阶段，需求、开发、测试由智能体执行，分别交付需求文档、可直接操作的工单管理系统和测试报告，成员审核把关。价值可见：任务完成后状态、代码合并和进展记录自动回到项目详情，进度同步到 100%，系统交付周期从 12 周缩短到 4 周。
