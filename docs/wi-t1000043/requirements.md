## 1. 项目背景与目标

### 1.1 输入状态与基线声明

本工作项的业务任务描述为占位符「1」，未包含实质业务内容。需求对象依据工作区上下文推断：

- 工作区 `docs/CIO演示场景.md` 描述「工单管理系统」研发任务，由通用应用开发智能体团队按 需求分析 → 开发实现 → 测试验证 执行，与本工作项的团队与阶段结构一致；
- 工作区 `docs/helpdesk-项目说明.md`（依据 Workbench 界面截图整理）提供完整的系统定位、功能架构与数据模型说明，本文档以其为主要需求素材。

据此，本基线将业务对象确定为**工单管理系统（Helpdesk 企业服务台）**。该对象选择为**推荐基线（推断）**，非用户在本工作项中明确声明；后续阶段获得用户澄清时，应优先按用户口径修订本文档。

### 1.2 问题与目标

系统面向 Chin Hin Group 集团，统一承接集团内部 IT、HR、薪酬（HR Services / Payroll）等服务请求，以「工单」为核心对象，提供受理、分配、SLA 时效管控、升级告警、审计追踪与智能辅助的完整闭环。

成功结果：

- 集团全体员工通过统一入口提交服务请求并跟踪处理进度；
- 各职能服务团队（Service Desk Team、HR Services Team、Payroll Team）高效受理与处理工单；
- 管理员掌握工单全貌，管控 SLA 时效，可追溯操作审计。

## 2. 角色与权限矩阵

| 角色 | 说明 | 能做 / 能看 | 不能 |
| --- | --- | --- | --- |
| 提单人 | 集团全体员工 | 提交服务请求、查看与跟踪自己的工单、接收通知 | 查看他人工单、管理系统配置 |
| 处理人 | 各职能服务团队成员（Service Desk / HR Services / Payroll） | 受理与处理工单、更新工单状态、关闭工单、接收分配通知 | 管理系统配置 |
| 系统管理员（System Admin） | 管理员视角（演示界面角色，可见全部部门工单） | 查看全部部门工单、分配与批量处理、管理公司 / 用户 / 部门 / 服务目录 / 分配规则 / SLA 配置、查看审计日志与 SLA 告警、导出工单列表 | —— |

> 权限说明：源素材仅明确 System Admin 的全量数据可见视角；提单人「仅见自己工单」、处理人「按受理团队可见」为通用服务台模式推导的**推荐基线**，非已确认的正式权限。

## 3. 用户旅程与关键场景

### 3.1 员工提交服务请求（提单人）

1. 员工进入系统，从服务目录选择服务项（如「重置密码」）；
2. 填写主题（支持中英双语）与描述，提交生成工单（编号形如 TK-2026-000247）；
3. 系统按分配规则自动分配受理团队与处理人，工单进入 Assigned 状态；
4. 员工在通知中心接收分配、状态变更、超时等事件通知；
5. 工单解决并关闭，员工可查看处理结果。

### 3.2 处理人处理工单（处理人）

1. 处理人进入 Workbench，按受理团队 / 本人过滤待处理工单；
2. 受理工单（Assigned → In progress）并处理；
3. 更新工单状态直至解决并关闭（Closed）；
4. 处理过程中 SLA 首次响应与解决时限持续监控，逾期呈现告警。

### 3.3 管理员监控与管控（System Admin）

1. 进入 Workbench，查看个性化问候与全局概览（数据范围、待分配工单数、SLA 告警数）；
2. 通过视图页签（All / Pending assign / SLA Alerts）与多维度筛选定位工单：关键字（工单号 / 主题）、Category、Priority、Status、SLA、组织维度（Group → BG → BU）叠加 Assignee、按 Updated at 排序；
3. 对待分配工单执行分配（单条或批量）；
4. 在 SLA alerts 告警中心集中处理超时 / 即将超时工单；
5. 需要线下汇报时导出工单列表；
6. 在系统管理区维护公司、用户、部门、服务目录、分配规则与 SLA 配置。

## 4. 核心实体与术语

| 术语 | 含义 | 用户可见关系 |
| --- | --- | --- |
| 工单 Ticket | 服务请求的载体 | 编号 TK-YYYY-NNNNNN（兼容历史编号如 TK-00112）；主题支持中英双语；列表中以主题 + 受理团队副行呈现 |
| 服务目录 Catalog | 可发起的标准化服务项定义 | 工单 Category 的来源 |
| 受理团队 Team | 职能服务团队 | Service Desk / HR Services / Payroll，显示于工单主题副行 |
| 优先级 Priority | P 级体系（示例 P2） | 工单列表列 |
| 工单状态 Status | Draft / Assigned / In progress / Closed | 工单列表列 |
| SLA | 首次响应（First Response）与解决（Resolution）两阶段时效 | 列表内联显示 Normal / Overdue（含逾期时长，如 Overdue by 23d 7h） |
| 组织架构 | Company / Group / BG / BU / Department 多级 | 筛选维度与数据可见范围控制 |
| 审计日志 Audit log | 工单及系统配置的操作记录 | 协作区入口，全程留痕 |
| 处理人 Assignee | 工单受理责任人 | 筛选维度、工单属性 |

## 5. 状态模型与业务规则

### 5.1 工单状态

| 状态 | 含义 |
| --- | --- |
| Draft | 草稿，尚未提交 |
| Assigned | 已分配到受理团队 / 处理人 |
| In progress | 处理中 |
| Closed | 已关闭（终态） |

状态转换：`Draft → Assigned → In progress → Closed`

通用约束：

- 状态沿上述方向前进，Closed 为终态；素材中未出现重新打开等逆向操作，不纳入本基线范围（见第 8 节）；
- 每次状态变更触发通知并写入审计日志（推荐基线）。

### 5.2 SLA 时效

- 两阶段时限：First Response（首次响应）、Resolution（解决）；
- 每阶段呈现 Normal / Overdue；逾期以红色标签加精确逾期时长显示（如 Overdue by 23d 7h）；
- SLA 形成「配置 → 监控 → 告警」闭环：SLA config 定义时限（推荐基线：可按优先级 / 目录差异化配置），列表内联监控，SLA alerts 模块与 Workbench 页签提供双重告警入口；
- SLA 时限到达仅翻转时效状态并进入告警，不自动关闭工单（推荐基线）。

### 5.3 工单编号规则

- 新工单编号：`TK-年份-六位序号`（如 TK-2026-000247）；
- 兼容历史编号格式（如 TK-00112）。

### 5.4 自动分配

- Assignment rules 按规则自动分配工单到受理团队 / 处理人；
- 分配未命中的工单停留在 Pending assign 队列等待人工分配，页签徽标实时显示数量；
- 分配异常不静默丢弃工单（推荐基线）。

## 6. 分模块功能需求

### 6.1 Workbench 工作台（核心页面）

**页面摘要区**

- 个性化问候（如 Hello System Admin, here is your ticket overview）；
- 全局概览指标：当前数据范围（All departments）、待分配工单数、SLA 告警数；
- 主操作：Export（导出）、New ticket（新建工单）。

**视图页签**

| 页签 | 说明 |
| --- | --- |
| All | 全部工单 |
| Pending assign | 待分配工单，徽标实时显示数量 |
| SLA Alerts | SLA 告警工单，徽标实时显示数量 |

页签右侧提供部门范围切换（All departments），控制整个列表的数据可见范围。

**筛选与排序**

- 关键字搜索：工单号（Ticket No.）或主题（Subject）；
- 工单属性：Category（分类）、Priority（优先级）、Status（状态）、SLA（时效状态）；
- 组织维度：Group → BG → BU 三级业务架构，叠加 Assignee（处理人）；
- 排序：按 Updated at（更新时间）。

**工单列表**

- 复选框支持多选（推荐基线：用于批量分配 / 导出 / 关闭）；
- 列：Ticket No.、Subject（副行显示受理团队）、Priority、Status、SLA - First Response、SLA - Resolution；
- 逾期 SLA 以红色标签呈现并注明逾期时长。

**不应发生的行为**

- 徽标数量与对应页签列表实际数量不一致；
- 越权用户在列表中看到超出其数据范围的工单（权限边界，推荐基线）；
- 筛选无结果时页面报错而非空态。

### 6.2 Dashboard（推荐基线，待确认）

数据仪表盘：工单量、SLA 达成率、团队负载等统计（源素材标注为推测）。

### 6.3 协作区

- **Audit log**：审计日志，追踪工单及系统配置的操作记录；
- **SLA alerts**：SLA 告警中心，集中呈现超时 / 即将超时的工单。

### 6.4 系统管理

| 模块 | 需求 |
| --- | --- |
| Companies | 公司管理，支持集团下多公司（多租户）架构 |
| Users | 用户管理 |
| Departments | 部门管理 |
| Catalog | 服务目录，定义可发起的标准化服务项 |
| Assignment rules | 工单自动分配规则 |
| SLA config | SLA 时效配置（首次响应时限、解决时限等） |
| Calendar | 日历（推荐基线：用于排班或 SLA 工作日历计算，待确认） |
| AI Agent | 智能体（推荐基线：自动应答、工单分类建议、知识库推荐，待确认） |

### 6.5 全局辅助能力

- **全局搜索**：支持 `⌘K` 快捷键唤起；
- **Notifications**：消息通知中心，推送分配、超时、状态变更等事件，显示未读计数（如 9+）；
- **Getting started**：新手引导清单，共 7 步，含「Start now」入口；
- **租户 / 身份切换**：顶部切换集团（Chin Hin Group）与角色（Admin）。

### 6.6 边界与异常（推荐基线）

- 筛选无结果：列表呈现空态，不报错；
- 分配规则未命中：工单留在 Pending assign 队列等待人工分配，不静默丢弃；
- SLA 逾期：翻转时效状态并进入告警中心，不自动关闭工单。

## 9. 验收场景

> 每条验收条件含稳定唯一编号；后续修改保留未变条件的编号。
> 强制程度：必须（Must）＝ 阻断验收；推荐（Should）＝ 推荐基线项，未达标记录为风险不阻断。
> 入口类型均为 UI（浏览器）——本基线为原型/界面驱动的业务系统，无纯后台/CLI 入口的验收条件。

### AC-01 新建工单与编号规则

- 强制程度：必须
- 入口类型：UI（浏览器）
- 适用角色：提单人
- 前置条件：用户已登录，服务目录中存在可用服务项
- 动作：在 Workbench 点击 New ticket，选择服务项，填写中英双语主题与描述，提交
- 预期结果：生成编号形如 TK-YYYY-NNNNNN 的工单并出现在工单列表，主题双语内容正确显示
- 证据类型：界面截图 / 操作录屏

### AC-02 Workbench 概览与视图页签

- 强制程度：必须
- 入口类型：UI（浏览器）
- 适用角色：系统管理员
- 前置条件：系统中存在不同状态的工单数据
- 动作：进入 Workbench，查看页面摘要区与视图页签，切换 All / Pending assign / SLA Alerts
- 预期结果：摘要区显示个性化问候、数据范围、待分配工单数与 SLA 告警数；页签徽标数量与对应列表实际数量一致
- 证据类型：界面截图 / 操作录屏

### AC-03 多维度筛选与排序

- 强制程度：必须
- 入口类型：UI（浏览器）
- 适用角色：系统管理员
- 前置条件：Workbench 打开且列表有数据
- 动作：依次使用关键字（工单号 / 主题）、Category、Priority、Status、SLA、组织维度（Group → BG → BU）叠加 Assignee 筛选，并按 Updated at 排序
- 预期结果：列表按筛选条件实时过滤，组合条件取交集，排序生效；无结果时呈现空态不报错
- 证据类型：界面截图 / 操作录屏

### AC-04 工单状态流转

- 强制程度：必须
- 入口类型：UI（浏览器）
- 适用角色：处理人
- 前置条件：存在 Assigned 状态的工单
- 动作：受理工单并处理，更新状态直至解决并关闭
- 预期结果：状态沿 Draft → Assigned → In progress → Closed 单向流转，列表状态列同步更新
- 证据类型：界面截图 / 操作录屏

### AC-05 SLA 时效展示与逾期告警

- 强制程度：必须
- 入口类型：UI（浏览器）
- 适用角色：系统管理员
- 前置条件：存在 SLA 已逾期的工单
- 动作：在工单列表查看 SLA - First Response 与 SLA - Resolution 列
- 预期结果：未逾期显示 Normal；逾期显示红色 Overdue 标签并注明精确逾期时长（如 Overdue by 23d 7h）
- 证据类型：界面截图

### AC-06 SLA 告警中心集中呈现

- 强制程度：必须
- 入口类型：UI（浏览器）
- 适用角色：系统管理员
- 前置条件：存在超时 / 即将超时的工单
- 动作：打开协作区 SLA alerts 模块，并对比 Workbench 的 SLA Alerts 页签
- 预期结果：两处入口均集中呈现告警工单，内容与徽标数量一致
- 证据类型：界面截图 / 操作录屏

### AC-07 自动分配与待分配队列

- 强制程度：必须
- 入口类型：UI（浏览器）
- 适用角色：系统管理员
- 前置条件：Assignment rules 已配置
- 动作：提交符合规则的新工单；提交不符合规则的新工单；查看 Pending assign 页签并人工分配
- 预期结果：符合规则的工单自动分配受理团队 / 处理人；不符合规则的工单进入 Pending assign 队列，人工分配后离开队列

### AC-08 数据范围切换

- 入口类型：UI（浏览器）

- 动作：在页签右侧切换部门范围（All departments ↔ 指定部门）
- 预期结果：整个列表的数据可见范围随切换更新，概览指标与页签徽标同步
- 证据类型：界面截图 / 操作录屏

- 适用角色：提单人
- 前置条件：存在双语主题的工单
- 动作：在工单列表查看该工单主题
- 预期结果：主题的中英双语内容（如「电脑无法开机 - PC/Laptop not turning on」）正确完整显示
- 证据类型：界面截图

### AC-16 新手引导

- 强制程度：推荐
- 入口类型：UI（浏览器）
- 适用角色：系统管理员
- 前置条件：管理员首次进入系统
- 动作：查看 Getting started 清单并点击 Start now
- 预期结果：7 步引导清单完整展示，Start now 入口可进入引导流程
- 证据类型：界面截图 / 操作录屏

## 10. 需求澄清说明

以下事项不阻塞本基线推进，但建议在后续阶段（或获得用户输入后）确认：

1. **业务对象确认**：本基线基于占位业务任务输入推断为工单管理系统（Helpdesk），依据见 1.1 节；如用户实际指向其他业务对象，本文档需整体修订；
2. **提单人 / 处理人的数据可见范围**：目前为推荐基线（AC-09）；
3. **Dashboard、Calendar、AI Agent**：源素材标注为推测，功能细节待确认；
4. **批量操作的具体动作集合**（批量分配 / 导出 / 关闭）：推荐基线，待确认。

> 结论：需求基线以「推荐基线 + 已确认素材」闭合，判定为 **ready**（可进入后续阶段）；上述待确认项均不构成阻塞。
