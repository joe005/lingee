# 项目与协作

## 目标与范围

项目统一在 Manage（管理）里立项和管理；Build 的协作开发不再有「项目」页签，只按任务协作：Manage 项目下的研发任务进入协作开发的任务列表，任务详情显示所属项目，成员执行并提交产物。旧的项目页入口和链接都回到「任务」。下文中协作开发内的项目管理描述为历史设计，保留供参考。

## 数据业务关系

| 对象 | 关键字段 | 关系与规则 |
| --- | --- | --- |
| 项目 | `projectId`、负责人、状态 | 项目是当前协作开发的核心对象；负责人来自可添加的协作成员。 |
| 项目成员 | `projectId`、`userId`、项目角色 | 从可用协作人员中搜索选择；角色为项目负责人、产品、开发、测试、参与者。 |
| 任务 | `taskId`、`projectId`、创建人、执行人、状态 | 任务归属项目；任务清单按创建时间倒序；任务可引用智能体/智能体团队（项目本身不绑定团队，新建任务时选择）。 |
| 产物 | `artifactId`、`taskId`、阶段序号、版本、状态 | 产物归属任务，在任务详情中查看；阶段序号用于稳定排序和预览。 |

原型用浏览器本地数据保存上述关系；正式实现以服务端主键和权限校验为准。

## 角色与权限

| 能力 | 管理员 | 项目负责人 | 项目成员 | 审核人 |
| --- | --- | --- | --- | --- |
| 管理协作成员 | 管理 | 查看 | 查看 | 查看 |
| 新建/编辑项目 | 管理 | 新建、编辑负责项目 | 查看 | 查看 |
| 添加/移除项目成员 | 管理 | 负责项目可管理 | 无 | 无 |
| 新建/分派任务 | 管理 | 管理负责项目 | 创建、执行 | 查看 |
| 提交产物 | 可 | 可 | 可 | 无 |
| 审核产物 | 可（被授权时） | 可（被授权时） | 无 | 通过/驳回 |
| 查看项目任务与历史产物 | 全部 | 负责项目 | 所属项目 | 授权范围 |

审核人必须被明确授权，不能因“能查看项目”自动获得审核权限。所有列表、详情和操作都按当前用户的项目成员关系过滤。

## 关键流程

1. 进入协作开发，查看项目列表。
2. 新建项目，填写名称和描述，添加成员并分配角色；保存后生成项目卡片。
3. 从项目卡片进入“任务清单”，查看该项目全部任务，倒序排列；工作台任务页不被改变。
4. 通过“智能创建任务”进入对话，在对话中选择项目、引用 `task-builder` 技能，确认后生成任务卡。
5. 负责人分派任务，成员执行并提交阶段产物；产物按阶段序号进入任务详情。
6. 审核人查看产物，选择通过或驳回；驳回必须填写原因，任务保留历史提交记录。
7. 项目负责人在详情页维护成员和任务入口；项目详情提供“概览 / 任务”页签，任务页签复用任务模块的列表视图并只显示当前项目的可见任务；产物在任务详情中查看，项目完成后保留只读历史。
8. 研发任务在执行人的 Lingee 桌面客户端本地执行，开始前检查本地开发环境，见下节「本地开发环境」。

历史协作页的任务删除与协作人员移除使用统一确认弹窗；弹窗写明对象及子任务保留、账号不删除等影响，默认聚焦“取消”。

## 本地开发环境

研发任务在执行人的 Lingee 桌面客户端本地执行。**一期只支持 HTTPS，用本机已有凭据或访问令牌授权；浏览器登录（OAuth）待平台授权应用就绪后接入；不提供 SSH。** 账号按人、按平台主机保存；项目目录按人、按电脑保存。

### 设置页

入口为协作开发顶部「设置」页签。灰画布上两张白卡，每行是独立的描边圆角条目。

- **打开不检测**：只展示上次检测结果（按人保存在本机，只有状态，不含凭据），从未检测过时显示「待检测」。检测只在点「检测」时发起，按钮左侧显示「上次检测 HH:MM」。登录或初始化成功后只重新检测相关平台和项目。
- **Git 账号**：右上角「检测」「＋ 添加账号」（主题色）。列出项目用到的平台、已登录的平台，以及 Gitee 等公有平台。列为平台（名称 + 主机）、账号（账号名 + 来源：本机凭据 / 访问令牌）、状态、操作（未登录为主色「登录」，已登录为「重新登录」）。
- **我的项目**：列出本人参与或负责、配置了代码仓库的项目。标题旁用橙色小字显示「N 个项目还没初始化」，全部就绪时不显示。列为项目（名称 + 仓库地址）、项目目录（默认 / 指定 + 路径）、状态、操作（未就绪「初始化」，已就绪「设置」，均为主色）；地址无效时显示「在项目设置中修正」。
- **没有安装 Git**：检测发现没有 Git 时，页面顶部提示「本机没有安装 Git，安装后点「检测」」，并提供「下载 Git」按系统打开官网下载页。Windows 客户端自带 MinGit，一般不会出现。

### 状态

| 状态 | 颜色 | 含义 |
| --- | --- | --- |
| 已就绪 | 绿 | 已登录，代码目录是该项目的 HTTPS 仓库 |
| 未初始化 | 黄 | 已登录，代码尚未下载到本机 |
| 未登录 | 橙 | 本机没有该平台的凭据 |
| 凭据失效 | 红 | 平台拒绝了保存的凭据（过期或被撤销） |
| 无权访问 | 橙 | 凭据有效，但账号没有该仓库的权限 |
| 无法连接 | 橙 | 网络不通或超时 |
| 目录不匹配 | 橙 | 绑定目录不是该项目的 HTTPS 仓库 |
| Git 不可用 | 橙 | 本机没有 Git |
| 地址无效 | 红 | 仓库地址不是 HTTPS（如 SSH 地址），需在项目设置中修正 |
| 待检测 | 灰字 | 还没检测过 |

账号状态只有可用、未登录、凭据失效、Git 不可用。检测时读取本机凭据后验证一次：有项目仓库时读一次仓库，没有时调用平台账号接口；验证失败不删除用户已保存的凭据。

### 登录与添加账号

- 同一个弹窗。从账号行或项目进入时平台已知，标题「登录 Git 账号」，副标题「主机 · 平台」；从「添加账号」进入时标题「添加 Git 账号」，先选平台（GitLab / GitHub / Gitee），GitLab 需填写平台地址。
- 只有「访问令牌」一项：密码框输入，不提供查看；右侧「去平台创建」打开平台令牌页并预填权限；下方一行说明所需权限（GitHub：repo；GitLab：read_user、read_repository、write_repository；Gitee：user_info、projects）和「令牌保存在系统钥匙串」，超长截断、悬停看全文。
- 「验证并登录」：令牌经平台账号接口验证后存入系统凭据库（macOS 钥匙串、Windows 凭据管理器），不写入 Lingee 配置文件，不进入对话。失败就近提示：格式不正确、无效或已过期、权限不足、无法连接、系统凭据库不可用。
- 一期没有退出登录，需要时到系统凭据库中删除。

### 初始化项目

- 弹窗标题「初始化项目」，从项目设置更改时为「更改项目目录」。顶部一行「账号：xxx · 主机」与「更换账号」；未登录时显示提示和「登录」，登录后回到本弹窗继续。
- 「代码保存位置」：默认 / 指定标签 + 路径，与上方文字左对齐。默认目录为工作区旁 `repositories/<平台主机>/<仓库路径>`，不同平台或组织的同名仓库不会共用目录。
- 「更改位置 / 使用已有代码」默认收起，可选默认目录或通过系统目录选择器选择本机已有代码。已有目录只校验是否为该项目的 HTTPS 仓库，不下载、不切分支、不改远端；不匹配时保留原代码和原绑定。
- 主按钮「初始化」（更改目录时「保存目录」），进行中显示「下载中…」或「校验中…」。下载先到临时目录，成功后才保存绑定。

### 项目设置

三行：Git 账号（「登录」或「更换账号」）、代码仓库（只读，在项目中维护）、项目目录（默认 / 指定 + 路径，「打开」「更改」）。未就绪时顶部一行说明原因。

### 任务自检与智能配置

- 任务开始前检查当前阶段处理人本机环境。本人手动启动且未就绪时进入「本地环境配置」对话或设置页；自动启动或他人触发时任务转为已阻塞并说明原因，由处理人配置后继续。
- 对话一次配置一个项目，登录与目录选择使用上面的共享弹窗；完成后从任务进入的显示「继续执行任务」。

### 原型边界与演示规则

- 登录、凭据读取、检测、下载和目录选择均为模拟，不访问平台、不修改本机凭据或代码；账号、绑定和检测结果按登录人保存在浏览器本地存储。
- 演示本机凭据为 github.com。令牌少于 8 位为格式错误，含 `expired` / `bad` 为无效，含 `readonly` 模拟无写权限（初始化后为「无权访问」）；目录选择器返回 `~/Projects/<仓库名>`，路径含 `other` 为不同仓库，含 `ssh` 为 SSH 目录（目录不匹配）。
- 设置页底部「演示：清空本机配置」「演示：模拟未安装 Git」只用于演示。

## 状态与异常

- 项目：进行中 → 已完成；归档后只读。
- 任务：待开始 → 进行中 → 待审核 → 已完成；驳回回到进行中并保留原因。
- 产物：草稿 → 待审核 → 已通过/已驳回；新版本不覆盖旧版本。
- 成员被移除后不能接收新任务，历史任务和产物仍可查看。
- 保存失败时保留本地旧数据并提示重试，不能生成半条项目或任务关系。

## 用户旅程

管理员或项目负责人进入协作开发 → 新建项目、添加成员和角色 → 成员从任务清单认领任务 → 通过智能创建对话补充任务信息 → 执行并提交带序号产物 → 审核人通过或驳回 → 项目负责人查看完整任务与产物历史并完成项目。

## 演示数据：问卷调研

「问卷调研系统建设」是汇报演示的贯穿项目（负责人吴宏超，演示任务预置通用应用开发智能体团队），预置 10 条任务，覆盖已完成、待审核（含一次驳回记录）、执行中、已阻塞、待开始和待规划。已有本地缓存的浏览器按任务编号补种一次，不覆盖已流转的任务。同一场景在其他页面的落点：应用开发的「问卷调研系统」卡片打开开发会话和本地问卷应用预览；通用应用和智能体的右侧预览是打开系统链接的内置浏览器，只保留前进、后退、刷新和地址栏，不显示苍穹应用的表单、列表、实体、插件、API、MCP 页签；技能开发预置「问卷设计」「问卷结果分析」及业务人员用的「问卷数据读取」「满意度指标口径」「分析报告生成」；智能体开发预置「问卷调研助手」。问卷系统上线后的智能体开发演示（对齐 lingee-build 智能体开发）：在智能体开发点「新建」进入对话创建，输入框带 agent-builder 技能、底部选中「智能体开发」，发送后生成「员工满意度分析助手」并展示「处理完成」、配置摘要和智能体卡片（本地测试）；右侧为智能体配置面板：名称、状态标签与编码，右上角保存 / 测试（本地测试、云端测试）/ 提交，页签为基础信息（头像、名称、领域、功能描述、模型策略、更新日志）、角色设定、技能配置、知识。测试打开「测试 · 员工满意度分析助手」会话，云端测试带「Console沙箱」标签，提示测试不触碰生产数据，可「返回主会话」；「提交」弹出「提交上架审核」确认，提交后状态为已提交，原型约 3 秒后模拟管理员审核通过并发布到 Work，智能体开发列表卡片同步显示已保存、已提交、已发布。配置面板的「在 Work 中使用」切到工作板块，在会话中选中该智能体提问，回答展示深度思考、调用技能与工具及分析结果。创建、审核与问答均为本地演示，不写入会话历史，刷新后恢复为未创建。

## 原型边界

人员、项目、任务、产物、角色和审核目前是本地模拟；正式版本需要服务端权限、并发锁和审计。

## 下拉选择

普通单选字段复用共享下拉组件，统一箭头、面板、选中标记与单边框焦点状态；支持键盘选择、禁用项和空值选项（如「全部」或「无」）。现有搜索、多选选择器保留原有能力，归档页面不迁移。
