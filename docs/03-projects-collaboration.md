# 项目与协作

## 目标与范围

项目统一在 Manage（管理）里立项和管理；Build 的协作开发不再有「项目」页签，只按任务协作：Manage 项目下的研发任务进入协作开发的任务列表，任务详情显示所属项目，成员执行并提交产物。旧的项目页入口和链接都回到「任务」。下文中协作开发内的项目管理描述为历史设计，保留供参考。

## 数据业务关系

| 对象 | 关键字段 | 关系与规则 |
| --- | --- | --- |
| 项目 | `projectId`、负责人、状态 | 项目是当前协作开发的核心对象；负责人来自可添加的协作成员。 |
| 项目成员 | `projectId`、`userId`、项目角色 | 从可用协作人员中搜索选择；角色为项目负责人、产品、开发、测试、参与者。 |
| 任务 | `taskId`、`projectId`、创建人、执行人、状态 | 任务归属项目；任务清单按创建时间倒序；任务可引用专家/专家团。 |
| 产物 | `artifactId`、`taskId`、阶段序号、版本、状态 | 产物归属任务，在任务详情中查看；阶段序号用于稳定排序和预览。 |

原型用浏览器本地数据保存上述关系；正式实现以服务端主键和权限校验为准。

## 角色与权限

| 能力 | 管理员 | 项目负责人 | 项目成员 | 审核人 |
| --- | --- | --- | --- | --- |
| 管理协作成员 | 管理 | 查看 | 查看 | 查看 |
| 新建/编辑项目 | 管理 | 新建、编辑负责项目 | 查看 | 查看 |
| 添加/移除项目成员 | 管理 | 负责项目可管理 | 无 | 无 |
| 新建/分派任务 | 管理 | 管理负责项目 | 创建、执行 | 查看 |
| 提交产物 | 可 | 可 | 可 | 无 |
| 审核产物 | 可（被授权时） | 可（被授权时） | 无 | 通过/驳回 |
| 查看项目任务与历史产物 | 全部 | 负责项目 | 所属项目 | 授权范围 |

审核人必须被明确授权，不能因“能查看项目”自动获得审核权限。所有列表、详情和操作都按当前用户的项目成员关系过滤。

## 关键流程

1. 进入协作开发，查看项目列表。
2. 新建项目，填写名称和描述，添加成员并分配角色；保存后生成项目卡片。
3. 从项目卡片进入“任务清单”，查看该项目全部任务，倒序排列；工作台任务页不被改变。
4. 通过“智能创建任务”进入对话，在对话中选择项目、引用 `task-builder` 技能，确认后生成任务卡。
5. 负责人分派任务，成员执行并提交阶段产物；产物按阶段序号进入任务详情。
6. 审核人查看产物，选择通过或驳回；驳回必须填写原因，任务保留历史提交记录。
7. 项目负责人在详情页维护成员和任务入口；项目详情提供“概览 / 任务”页签，任务页签复用任务模块的列表视图并只显示当前项目的可见任务；产物在任务详情中查看，项目完成后保留只读历史。

## 状态与异常

- 项目：进行中 → 已完成；归档后只读。
- 任务：待开始 → 进行中 → 待审核 → 已完成；驳回回到进行中并保留原因。
- 产物：草稿 → 待审核 → 已通过/已驳回；新版本不覆盖旧版本。
- 成员被移除后不能接收新任务，历史任务和产物仍可查看。
- 保存失败时保留本地旧数据并提示重试，不能生成半条项目或任务关系。

## 用户旅程

管理员或项目负责人进入协作开发 → 新建项目、添加成员和角色 → 成员从任务清单认领任务 → 通过智能创建对话补充任务信息 → 执行并提交带序号产物 → 审核人通过或驳回 → 项目负责人查看完整任务与产物历史并完成项目。

## 演示数据：问卷调研

「问卷调研系统建设」是汇报演示的贯穿项目（负责人吴宏超，绑定通用应用开发专家团），预置 10 条任务，覆盖已完成、待审核（含一次驳回记录）、执行中、已阻塞、待开始和待规划。已有本地缓存的浏览器按任务编号补种一次，不覆盖已流转的任务。同一场景在其他页面的落点：应用开发的「问卷调研系统」卡片打开开发会话和本地问卷应用预览；通用应用和智能体的右侧预览是打开系统链接的内置浏览器，只保留前进、后退、刷新和地址栏，不显示苍穹应用的表单、列表、实体、插件、API、MCP 页签；技能开发预置「问卷设计」「问卷结果分析」及业务人员用的「问卷数据读取」「满意度指标口径」「分析报告生成」；智能体开发预置「问卷调研助手」。问卷系统上线后的智能体开发演示（对齐 lingee-build 智能体开发）：在智能体开发点「新建」进入对话创建，输入框带 agent-builder 技能、底部选中「智能体开发专家」，发送后生成「员工满意度分析助手」并展示「处理完成」、配置摘要和智能体卡片（本地测试）；右侧为智能体配置面板：名称、状态标签与编码，右上角保存 / 测试（本地测试、云端测试）/ 提交，页签为基础信息（头像、名称、领域、功能描述、模型策略、更新日志）、角色设定、技能配置、知识。测试打开「测试 · 员工满意度分析助手」会话，云端测试带「Console沙箱」标签，提示测试不触碰生产数据，可「返回主会话」；「提交」弹出「提交上架审核」确认，提交后状态为已提交，原型约 3 秒后模拟管理员审核通过并发布到 Work，智能体开发列表卡片同步显示已保存、已提交、已发布。配置面板的「在 Work 中使用」切到工作板块，在会话中选中该智能体提问，回答展示深度思考、调用技能与工具及分析结果。创建、审核与问答均为本地演示，不写入会话历史，刷新后恢复为未创建。

## 演示数据：设备巡检维修

「设备巡检维修系统建设」是汇报 6.1 / 6.2 的贯穿项目，在 Manage 立项（负责人张工，在金蝶 ERP 上建设，绑定苍穹应用开发专家团；T1001503 的开发实现阶段产物是元数据清单，应用开发里该系统的列表、实体、插件页签展示本系统的元数据），预置 T1001500–T1001506：T1001503「故障报修与维修记录」停在测试验证待张工审核；T1001506「设备故障诊断助手」由设备主管周建国（新增演示账号）负责，只由「智能体开发」一个智能体执行，停在测试验证待周建国审核。已有本地缓存的浏览器按任务编号补种一次。同一场景在其他页面的落点：应用开发「设备巡检维修系统」打开运行中的系统预览；技能开发预置「查询设备档案」「查询维修记录」；智能体开发「设备故障诊断助手」初始为已保存，可从「⋯」菜单提交上架审核，点卡片打开维修工提问的对话。演示步骤见 [设备运维演示场景.md](设备运维演示场景.md)。

## 原型边界

人员、项目、任务、产物、角色和审核目前是本地模拟；正式版本需要服务端权限、并发锁和审计。

## 下拉选择

普通单选字段复用共享下拉组件，统一箭头、面板、选中标记与单边框焦点状态；支持键盘选择、禁用项和空值选项（如「全部」或「无」）。现有搜索、多选选择器保留原有能力，归档页面不迁移。
