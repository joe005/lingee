# 项目与协作

## 目标与范围

项目统一在 Manage（管理）里立项和管理；Build 的协作开发不再有「项目」页签，只按任务协作：Manage 项目下的研发任务进入协作开发的任务列表，任务详情显示所属项目，成员执行并提交产物。旧的项目页入口和链接都回到「任务」。下文中协作开发内的项目管理描述为历史设计，保留供参考。

## 数据业务关系

| 对象 | 关键字段 | 关系与规则 |
| --- | --- | --- |
| 项目 | `projectId`、负责人、状态 | 项目是当前协作开发的核心对象；负责人来自可添加的协作成员。 |
| 项目成员 | `projectId`、`userId`、项目角色 | 从可用协作人员中搜索选择；角色为项目负责人、产品、开发、测试、参与者。 |
| 任务 | `taskId`、`projectId`、创建人、执行人、状态 | 任务归属项目；任务清单按创建时间倒序；任务可引用智能体/智能体团队（项目本身不绑定团队，新建任务时选择）。 |
| 产物 | `artifactId`、`taskId`、阶段序号、版本、状态 | 产物归属任务，在任务详情中查看；阶段序号用于稳定排序和预览。 |

原型用浏览器本地数据保存上述关系；正式实现以服务端主键和权限校验为准。

## 角色与权限

| 能力 | 管理员 | 项目负责人 | 项目成员 | 审核人 |
| --- | --- | --- | --- | --- |
| 管理协作成员 | 管理 | 查看 | 查看 | 查看 |
| 新建/编辑项目 | 管理 | 新建、编辑负责项目 | 查看 | 查看 |
| 添加/移除项目成员 | 管理 | 负责项目可管理 | 无 | 无 |
| 新建/分派任务 | 管理 | 管理负责项目 | 创建、执行 | 查看 |
| 提交产物 | 可 | 可 | 可 | 无 |
| 审核产物 | 可（被授权时） | 可（被授权时） | 无 | 通过/驳回 |
| 查看项目任务与历史产物 | 全部 | 负责项目 | 所属项目 | 授权范围 |

审核人必须被明确授权，不能因“能查看项目”自动获得审核权限。所有列表、详情和操作都按当前用户的项目成员关系过滤。

## 关键流程

1. 进入协作开发，查看项目列表。
2. 新建项目，填写名称和描述，添加成员并分配角色；保存后生成项目卡片。
3. 从项目卡片进入“任务清单”，查看该项目全部任务，倒序排列；工作台任务页不被改变。
4. 通过“智能创建任务”进入对话，在对话中选择项目、引用 `task-builder` 技能，确认后生成任务卡。
5. 负责人分派任务，成员执行并提交阶段产物；产物按阶段序号进入任务详情。
6. 审核人查看产物，选择通过或驳回；驳回必须填写原因，任务保留历史提交记录。
7. 项目负责人在详情页维护成员和任务入口；项目详情提供“概览 / 任务”页签，任务页签复用任务模块的列表视图并只显示当前项目的可见任务；产物在任务详情中查看，项目完成后保留只读历史。
8. 研发任务在执行人的 Lingee 桌面客户端本地执行，开始前检查本地开发环境，见下节「本地开发环境」。

历史协作页的任务删除与协作人员移除使用统一确认弹窗；弹窗写明对象及子任务保留、账号不删除等影响，默认聚焦“取消”。

## 本地开发环境

研发任务在执行人的 Lingee 桌面客户端本地执行。**一期只支持 HTTPS，用本机已有凭据或访问令牌授权；浏览器登录（OAuth）待平台授权应用就绪后接入；不提供 SSH。** 账号按人、按平台主机保存；项目目录按人、按电脑保存，与任务执行使用同一目录。

### 设置页

设置容器固定在页面剩余高度内，顶部页签与左侧导航不随右侧内容滚动；右侧内容区独立滚动；成员页仅人员列表框内部滚动，标题、添加按钮、人数统计与分页固定。添加成员的候选下拉在自身列表内滚动，滚动到边界不带动外层页面。

顶部「设置」采用左侧分类、右侧内容的布局：基础分组仅保留「Git 账号」，工作区设置分组包含「通用、仓库、成员、智能体与团队」。范围取顶部所选空间或工作区；未选择范围时自动选中用户默认范围或第一个可访问的开发空间，无可用空间时提示先创建或加入空间。

- 通用：维护名称、描述；空间另可维护上下文（空间指令）。
- 工作区通用设置只展示名称和描述，不展示创建者；创建者记录仍保留于数据中。
- 仓库：空间 / 工作区维护多仓库列表，按独立卡片平铺展示，常规窗口固定两列、窄屏单列，与 Git 账号卡片统一列数和间距，默认紧凑展示仓库名称，地址后紧接分支标签并保持同一行，下一行展示目录摘要：默认方式仅显示「默认目录」，自定义方式显示具体路径，长路径省略并悬停显示完整内容，目录配置操作保留在编辑弹窗；点击「编辑」打开弹窗，保存后关闭并刷新卡片，取消恢复编辑前内容；网格中的「新增仓库」卡片打开新增弹窗；空列表不展示数量和空态占位，仅从左侧第一格展示新增卡片。卡片固定紧凑间距，头部为仓库名称、主仓库标记及右上角统一文字操作：编辑、设为主仓库、删除直接展示，不再提供更多菜单，删除仍需确认，仅删除当前工作区关联，不删除远端仓库和本机文件，编辑表单参考 Manage 新建空间，仅编辑 Git 地址（HTTPS）和基准分支（main / master / develop 或自定义），弹窗参考初始化仓库设计：标题下展示当前工作区，上方「代码仓库」一组内并排放地址与分支，下方「本机目录」采用上下两张单选卡，选中描边高亮；默认卡展示路径，自定义卡选中后提供输入和选择文件夹，底部独立操作栏为取消／保存；不再展示描述和关联应用，已有元数据保留。新增和编辑仅在弹窗内保存；卡片外层不再提供保存按钮，主仓库切换和确认删除即时保存；保存前校验账号、地址、分支与模拟可访问性，列表按规范化地址去重；底部保留「+ 添加仓库」，不提供创建临时仓库入口。移除仓库页顶部的用途说明、令牌提示条和管理令牌按钮。当前工作区只有一处本机配置入口：各仓库卡片下直接展示本机工作目录，在新增和编辑弹窗中直接提供「默认目录／自定义目录」两种方式；默认目录随仓库地址生成，自定义目录可选择文件夹或输入路径，点击保存时先校验目录，再与仓库配置一并保存，沿用现有初始化、目录校验与任务读取的绑定记录；新加仓库或修改地址、分支时即可选择目录，不再要求先保存；取消弹窗不写入目录绑定。团队共享仓库配置，本机目录仍按当前用户设备保存，普通成员也可配置自己的目录。各工作区独立维护列表，不再提供继承、独立配置或恢复继承。旧版已保存的继承配置按原有效列表固化，不再随上级改变；新工作区初始为空。每个非空列表有一个主仓库，首个添加的仓库自动成为主仓库，可通过「设为主仓库」切换并即时保存；移除主仓库后自动选取剩余首项。任务自动使用主仓库。不提供代码子目录。旧单仓库缓存兼容为一项列表，旧局部覆盖与显式继承记录在保存配置前固定为独立列表；不回写 Manage 仓库字段。
- 成员：顶部「添加成员」展开搜索添加栏，可按姓名、邮箱、手机号或工号匹配已有人员；选择候选人后才能添加，空间可选择成员或管理员，工作区只支持成员并仅列空间内人员。成员列表支持分页，默认每页 10 条，可切换为 20 / 50 条，显示总数、当前页及上一页/下一页；切换空间或工作区回到第一页，添加成功定位到新增成员所在末页，删除后自动校正页码。列表展示头像首字、姓名、已有邮箱、部门及角色，移出收在行尾更多菜单；无匹配结果显示空态。展示负责人、管理员、成员，按权限添加或确认移出；工作区只能添加空间成员。负责人、有未完成任务或负责工作区的成员须先转交；移出空间同时移出其工作区成员关系。
- 权限与保存：沿用空间和工作区管理权限；无权限或工作区已归档时只读，保存失败回滚。不再提供独立的「工作区管理」入口与页面；工作区创建仍从顶部空间树的加号进入，基本信息与成员在通用、成员分类维护。

个人 Git 账号在基础分组管理；独立「本机环境」导航入口移除，环境配置的旧入口统一跳转当前工作区的「仓库」，不再展示全局仓库环境清单。工作区内支持多个仓库，各仓库分别绑定本机目录。

- **账号配置入口**：未配置 Git 账号时不显示顶部提示条和「立即配置」按钮，通过 Git 账号卡片的「添加」或行内「登录」配置；本机未安装 Git、令牌即将到期的异常提示仍保留。
- **打开不检测**：只展示上次检测结果（按人保存在本机，只有状态，不含凭据），从未检测过时显示「待检测」。检测只在点「检测」时发起，按钮左侧显示「上次检测 HH:MM」。登录或初始化成功后只重新检测相关平台和空间。
- **Git 账号**：只列已登录的账号，未登录的平台不占位；没有账号时显示空状态「还没有登录 Git 账号」和「添加账号」。不分组，两列平铺卡片，左侧为各平台自己的标识（`ui.js` 的 `ldPlatformLogo`，账号卡片与登录弹窗的平台下拉共用；金蝶标识取官网 logo 的四色圆点，待换官方矢量素材），按平台固定顺序（金蝶 GitLab、GitHub、Gitee、其他 GitLab）再按主机排序，异常卡片不置顶。卡片：账号名 + 状态标签（可用绿色、即将过期、凭据失效、无法连接、Git 不可用；没检测过的已登录账号默认显示「可用」；单账号检测时显示「检测中…」）、「主机 · 来源 · 到期日」。到期日只在平台读得到时显示（GitHub 读响应头 `github-authentication-token-expiration`，GitLab 读 `/personal_access_tokens/self`，Gitee 和本机凭据读不到则不显示、也不出现「即将过期」，失效仍以平台接口 401 为准）；已过期显示「已于 日期 过期」。悬停出现「···」菜单：重新登录、检测（只检测这个账号，完成后 toast 给结果）、删除；无法连接时「检测」排第一，因为网络问题重新登录解决不了。来源为「本机凭据」（检测系统里原有的，终端等其他工具也在用）的账号不是 Lingee 保存的，菜单只有重新登录和检测，不提供删除或移除；访问令牌来源才有「删除」，只清除 Lingee 写入凭据库的那一条（`git credential reject`），确认弹窗写明终端和其他 Git 工具访问该主机也会失效。空间用到但未登录的平台在「我的空间」行内显示「登录」。右上为白底「检测」和主色「＋ 添加」；有令牌即将到期时顶部浅橙提示条，右侧「重新登录」；Git 未安装时提示条替换为蓝色文字链接「安装Git」。
- **本机目录**：在当前工作区仓库卡片中就地配置，默认复用同一用户当前设备上该仓库的已有目录；可通过目录配置弹窗选择默认或自定义目录，沿用原有校验、初始化、运行任务保护与任务目录快照。不同仓库不会绑定到同一个目录；工作区层级不代表磁盘目录父子关系。
- **地址与连通提示**：地址不规范、无法连接或仓库不存在时就近显示原因。仓库配置统一提示到 Build「设置 › 工作区设置 › 仓库」修改；格式校验实时进行，可访问性在保存、检测和初始化时模拟检查。
  - **地址不规范**实时判断，不用检测（Manage 新建空间和修改代码仓库时已用同一套规则静态校验，这里兜底校验前录入的地址）：规则见 Manage 文档 07-manager.md（不像地址、仓库网页地址、GitHub / Gitee 地址不完整；GitLab 和其他私有云平台不查段数）。新建空间粘贴地址时用同一套提示。
  - **无法连接 / 仓库不存在**在「检测」和初始化时检查（`git ls-remote`）；初始化前检查不通过时在初始化弹窗里提示，不下载、不改目录。结果保留到下次检测或初始化成功。
  - 顶部提醒按仓库去重显示「N 个仓库环境未就绪」，浮层提供对应操作。
- **新建空间**：设置页不提供新建入口，任务空间下拉保留既有新建流程；创建时保存共享仓库配置，不下载代码、不选择本机目录。Manage 页面与创建表单本轮不调整。
- **未初始化不用检测**：仓库没有本机绑定即为未初始化；目录丢失时显示「目录丢失」和「重新绑定」，原绑定保留至重新绑定成功。
- **加载失败**：空间清单加载失败时顶部提示「空间加载失败，请重试」并提供「重试」，不显示空列表文案；没有空间时显示「暂无空间」。
- **没有安装 Git**：检测发现没有 Git 时，页面顶部提示「本机没有安装 Git，安装后点「检测」」，并提供「下载 Git」按系统打开官网下载页。Windows 客户端自带 MinGit，一般不会出现。

### 状态

| 状态 | 颜色 | 含义 |
| --- | --- | --- |
| 已就绪 | 绿 | 已登录，本机目录绑定当前仓库 |
| 未初始化 | 黄 | 当前仓库尚无本机绑定 |
| 未登录 | 橙 | 本机没有该平台的凭据 |
| 凭据失效 | 红 | 平台拒绝了保存的凭据（过期或被撤销） |
| 无权访问 | 橙 | 推送校验（`git push --dry-run`）没通过，按原因提示：令牌没有写权限 → 重新创建令牌并登录；账号在仓库里角色不够（GitLab 需 Developer+、GitHub 需 Write+）→ 显示「待管理员授权」，请空间管理员升角色；GitHub 组织开启 SAML SSO 而令牌未授权 → 到令牌页「Configure SSO › Authorize」后重新登录 |
| 无法连接 | 橙 | 连不上仓库所在平台（网络、代理或未连内网 VPN） |
| 仓库不存在 | 红 | 登录后仍拿不到仓库：地址有误，或账号没有访问权限（平台不区分） |
| 目录不匹配 | 橙 | 本机目录的仓库与当前仓库不一致 |
| 目录丢失 | 橙 | 已绑定目录被移走或删除，需要重新绑定 |
| 可清理 | 橙 | 无有效使用范围且无进行中任务，仅手动移除绑定记录 |
| Git 不可用 | 橙 | 本机没有 Git |
| 地址不规范 | 红 | Git 地址格式不对，显示具体原因和正确写法，需由能管理空间的人修改 |
| 未配置仓库 | 灰字 | 空间没有填写代码仓库，需在空间设置中填写 |
| SSH 仓库 | 灰字 | 一期不支持 SSH 地址：提示在 Build 仓库设置把代码仓库改成 HTTPS 地址后再登录 Git 账号，操作列显示「待改 HTTPS 地址」 |
| 待检测 | 灰字 | 还没检测过 |

账号状态有可用、即将过期、未登录、凭据失效、无权访问、无法连接、Git 不可用；凭据失效（平台返回 401 或已过期）与无法连接（超时、拒绝连接，多为网络或 VPN）要分开，处理方式不同。检测用 `git credential fill`（protocol=https、host=<主机>）查询系统凭据库里是否存了这个主机的凭据，再用该凭据调用平台账号接口验证一次；**不能以 `ls-remote` / `clone` 成功为准**：公开仓库匿名就能读，读成功不代表本机有凭据，推送时照样鉴权失败。推送权限单独用 `GIT_TERMINAL_PROMPT=0 git push --dry-run origin HEAD:refs/heads/_cred-probe` 校验（不会真推送、不建远端分支），在初始化和登录后执行。连不上平台立即停止；验证失败不删除用户已保存的凭据。

令牌到期前 7 天账号状态显示「即将过期」（橙），设置页顶部提示「<主机> 的访问令牌将于 <日期> 到期，到期后拉取和推送会失败」和「重新登录」；执行任务前也会提醒一次，不拦截。凭据是设备级的，每台电脑各自登录一次。

### 登录与添加账号

- 同一个弹窗，上下排版：「平台」下拉（金蝶 GitLab / GitHub / Gitee / 其他 GitLab）、「Git 账号」（只读显示「主机 · 平台」，选其他 GitLab 时填写平台地址）、「访问令牌」（右上「去平台创建」）、常显的「如何获取访问令牌」按平台步骤。从账号卡片或空间进入时平台已知并锁定，标题「登录 Git 账号」；从「添加」进入标题「添加 Git 账号」。
- 只有「访问令牌」一项：密码框输入，不提供查看；右侧「去平台创建」在浏览器中打开平台真实的令牌创建页：GitHub、GitLab 通过地址参数预填令牌名称（Lingee）和所需权限（GitLab 较新版本才支持预填），Gitee 只打开页面；下方一行提示「登录后令牌会写入系统 Git 凭据库，终端和智能体里的 Git 操作都能使用」，系统里该主机已有凭据时追加「系统里已有 {主机} 的凭据（{用户名}），登录后会被这个令牌覆盖」。再下方是默认收起的「如何获取访问令牌？」，展开后按所选平台列出步骤：进入令牌页面；勾选所需权限（GitHub：经典令牌 repo，或细粒度令牌 Contents 设为 Read and write；GitLab：read_user、read_repository、write_repository，并选到期时间；Gitee：user_info、projects）；GitHub 组织开启 SSO 时在令牌旁点「Configure SSO › Authorize」；复制令牌（只显示一次）粘贴到上方。GitLab 步骤里带出平台地址。
- 「验证并登录」：令牌经平台账号接口验证后写入系统 Git 凭据库（相当于 `git credential approve`，由 Git 的凭据助手存入 macOS 钥匙串、Windows 凭据管理器），Lingee 只记用户名、主机、到期日，不另存令牌，不进入对话。失败就近提示：格式不正确、无效或已过期、权限不足、无法连接；本机未安装 Git 时提示「请先安装 Git 后再登录」，不放行。
- 一期没有退出登录，需要时到系统凭据库中删除。

### 初始化仓库与本机目录设置

列表「初始化」或任务首次执行打开现有表单：只读仓库与基准分支、按主机匹配的 Git 账号、默认 / 自定义本机目录。默认路径为 `<本机根目录>/<仓库名>`，不同主机或所有者的同名仓库增加前缀；空间改名不改变绑定。同仓库默认跨空间 / 工作区复用克隆；需要长期隔离时按范围配置独立目录。

本机目录必须在根目录内，一个目录不能绑定不同仓库；目录被未结束任务使用时禁止更换或解绑；工作范围有未结束任务时禁止切换所用目录。选择不匹配的仓库目录、冲突文件或保存失败时保留原绑定与原目录。已绑定时标题「本机目录设置」，未绑定时「初始化仓库」；目录丢失可重新绑定。进度、停止、后台初始化与准备执行环境复用原控件，同仓库不能并行重复初始化。

首次启动任务保存仓库和目标分支快照；在克隆下记录独立任务目录，工作目录为独立任务目录。目录绑定在启动时记录到当前用户的任务目录记录，后续阶段与重试沿用该记录。路径只保存在当前用户本机配置，不进入团队任务快照；真实 clone / worktree 由客户端实现，当前原型仅模拟记录和进度。

### 任务自检与智能配置

- （客户端一期未实现，目前由协作后端在任务开始时判断仓库是否就绪）任务开始前检查当前阶段处理人本机环境。本人手动启动且未就绪时打开「准备执行环境」弹窗；自动启动或他人触发时任务转为已阻塞并说明原因，由处理人配置后继续。
- 执行前检查只读本机信息（目录绑定、目录、仓库远端、Git 是否可用），不联网；同一仓库配置 3 秒内多次启动复用结果。已初始化直接执行；未初始化时本人手动启动打开「准备执行环境」（`#ldPrepOverlay`）：顶部蓝色说明「首次在本机使用此仓库执行任务，需要准备以下环境。完成后将继续当前任务。」，下方与初始化仓库同一套表单，主按钮「完成并执行」，成功后继续原任务，取消则任务保持原状态。
- **Git 未安装**：设置页顶部、准备执行环境、空间卡片给「安装 Git」，点击新建「安装 Git」对话（归到发起的空间下，出现在左侧对话列表；设置页顶部发起时归到第一个开发空间）并自动发送预置提示词（`composer/git-install-chat.js`），智能体检查系统、征得确认后安装并验证；提示条随进度变为「正在新对话中安装 Git」「需要你在对话中确认」「安装未完成」，完成后 toast「Git 安装完成」并自动检测。从准备执行环境发起时关闭弹窗，装好后重新开始任务。安装过程为演示脚本，不执行真实命令。

### 新建空间

任务的空间下拉继续使用既有「新建空间」弹窗：名称、目标、Git 地址和基准分支。仓库地址按平台凭据模拟校验；允许不同空间复用同仓库。创建只调用现有空间接口登记名称、目标与负责人，再单独保存 Build 仓库配置；主按钮为「创建空间」，不拉取代码、不绑定本机目录。空间创建成功而配置保存失败时明确提示在 Build 仓库设置重试，不重复建空间。本轮不修改 Manage 页面或接口定义。

### 原型边界与演示规则

- 登录、凭据读取、检测、下载和目录选择均为模拟，不访问平台、不修改本机凭据或代码；账号、绑定和检测结果按登录人保存在浏览器本地存储。
- 演示本机凭据为 github.com。令牌少于 8 位为格式错误，含 `expired` / `bad` 为无效，含 `readonly` 模拟令牌没有写权限、含 `norole` 模拟仓库角色不够、GitHub 令牌含 `sso` 模拟未授权组织 SSO（初始化后均为「无权访问」，原因各不相同）；含 `soon` 的令牌 5 天后到期，用于演示到期提醒。公司 GitLab 主机名为 `git.kingdee.com`，旧缓存里按 `gitlab.kingdee.com` 保存的账号会自动迁移。
- 本机根目录演示为 `~/lingeebuild/workspaces/<身份>`；默认目录使用仓库名。目录包含 `outside`、`other`、`conflict` 分别模拟越界、错误仓库、文件冲突；已绑定目录带 `missing-dir` 或记录 `directoryMissing` 模拟目录丢失。真实目录与 Git 操作不在浏览器原型中执行。
- 设置页底部「演示：清空本机配置」「演示：模拟未安装 Git」「演示：模拟网络不通」只用于演示；模拟网络不通后点「检测」或初始化，HTTPS 仓库都显示「无法连接」。已有空间的地址含 `offline` 也视为连不上，含 `private` / `missing`（已登录时）视为仓库不存在。
- 新建空间和仓库保存时的访问检查为模拟：地址含 `offline` 视为无法连接，含 `private` / `missing` 视为不存在或无权访问；仓库配置单独存在 Build 原型存储，账号和目录仍按当前用户保存在浏览器本机存储。

## 状态与异常

- 首次进入协作开发先保留侧栏与顶部页签，HTML 首屏即显示固定居中的 16px 中性灰转圈与「加载中…」短文案，覆盖主脚本下载与业务初始化的完整等待过程，不延迟到模块就绪后再显示；加载期间不显示零数量、空态和未就绪操作。顶部导航不再显示工作区设置（齿轮）图标；顶部导航从 HTML 首屏使用相同字号、间距与高度，不依赖内容面板激活后再切换样式；加载区不切换占位布局、不使用呼吸和进场动效，提示文字固定宽度，重试按钮在下方独立定位，不挤动加载提示；初始化分段执行，数据与首屏就绪后一次展示完整内容；再次进入直接复用数据。
- 加载超过 10 秒提示「加载较慢…」并提供轻量文字按钮「重试」；重试先停止当前初始化再重新执行，避免并发加载。明确失败时显示「加载失败」和「重试」，不刷新整页、不清除本地数据。加载中切页签以最后一次选择为准，离开协作开发后不主动切回。

- 空间：进行中 → 已完成；归档后只读。
- 任务：待开始 → 进行中 → 待审核 → 已完成；驳回回到进行中并保留原因。
- 产物：草稿 → 待审核 → 已通过/已驳回；新版本不覆盖旧版本。
- 成员被移除后不能接收新任务，历史任务和产物仍可查看。
- 保存失败时保留本地旧数据并提示重试，不能生成半条空间或任务关系。

## 用户旅程

管理员或空间负责人进入协作开发 → 新建空间、添加成员和角色 → 成员从任务清单认领任务 → 通过智能创建对话补充任务信息 → 执行并提交带序号产物 → 审核人通过或驳回 → 空间负责人查看完整任务与产物历史并完成空间。

## 下拉选择

普通单选字段复用共享下拉组件，统一箭头、面板、选中标记与单边框焦点状态；支持键盘选择、禁用项和空值选项（如「全部」或「无」）。现有搜索、多选选择器保留原有能力，归档页面不迁移。

窄窗口下协作开发顶部导航自动换行，任务、智能体、智能体团队及设置入口不压缩截断，环境提示继续可达。

初始化仓库与本机目录设置弹窗完整展示代码仓库地址（保留协议前缀，长地址换行，可选中复制）。当前账号按平台主机共用；「更换账号」重新授权该平台，并影响同一平台下的其他空间，不提供每个空间独立选择多个账号的能力。

初始化以当前解析配置或任务快照中的基准分支为准，完整展示仓库 URL，参照 Manage 的 Git 设置，仓库地址在左、带分支图标的具体分支在右，两项均只读，长内容换行；不单列基准分支说明；分支读取解析结果，不固定为 main；获取该远端分支最新代码，再准备本机目录并校验权限。进度区从 0% 显示到 100%，按「校验仓库访问权限 → 获取基准分支最新代码 → 准备本机代码目录 → 校验分支与推送权限」展示当前阶段。已有仓库先获取更新，未提交改动不得被覆盖；完成后继续原任务。当前进度与 Git 操作为原型模拟。

初始化与本机目录设置复用现有表单与分阶段进度；原型不读取真实文件系统，也不执行 clone 或 worktree。

开始初始化后，进度条置于弹窗内容顶部并滚动到可见位置，主提示为「正在初始化，请稍候」，补充说明大型仓库可能耗时较长、请保持网络连接；按钮显示「正在初始化…」并禁止重复提交。进度到 100% 后显示完成，原型使用延长的模拟过程展示等待效果。
