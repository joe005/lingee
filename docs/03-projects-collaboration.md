# 项目与协作

## 目标与范围

项目统一在 Manage（管理）里立项和管理；Build 的协作开发不再有「项目」页签，只按任务协作：Manage 项目下的研发任务进入协作开发的任务列表，任务详情显示所属项目，成员执行并提交产物。旧的项目页入口和链接都回到「任务」。下文中协作开发内的项目管理描述为历史设计，保留供参考。

## 数据业务关系

| 对象 | 关键字段 | 关系与规则 |
| --- | --- | --- |
| 项目 | `projectId`、负责人、状态 | 项目是当前协作开发的核心对象；负责人来自可添加的协作成员。 |
| 项目成员 | `projectId`、`userId`、项目角色 | 从可用协作人员中搜索选择；角色为项目负责人、产品、开发、测试、参与者。 |
| 任务 | `taskId`、`projectId`、创建人、执行人、状态 | 任务归属项目；任务清单按创建时间倒序；任务可引用智能体/智能体团队（项目本身不绑定团队，新建任务时选择）。 |
| 产物 | `artifactId`、`taskId`、阶段序号、版本、状态 | 产物归属任务，在任务详情中查看；阶段序号用于稳定排序和预览。 |

原型用浏览器本地数据保存上述关系；正式实现以服务端主键和权限校验为准。

## 角色与权限

| 能力 | 管理员 | 项目负责人 | 项目成员 | 审核人 |
| --- | --- | --- | --- | --- |
| 管理协作成员 | 管理 | 查看 | 查看 | 查看 |
| 新建/编辑项目 | 管理 | 新建、编辑负责项目 | 查看 | 查看 |
| 添加/移除项目成员 | 管理 | 负责项目可管理 | 无 | 无 |
| 新建/分派任务 | 管理 | 管理负责项目 | 创建、执行 | 查看 |
| 提交产物 | 可 | 可 | 可 | 无 |
| 审核产物 | 可（被授权时） | 可（被授权时） | 无 | 通过/驳回 |
| 查看项目任务与历史产物 | 全部 | 负责项目 | 所属项目 | 授权范围 |

审核人必须被明确授权，不能因“能查看项目”自动获得审核权限。所有列表、详情和操作都按当前用户的项目成员关系过滤。

## 关键流程

1. 进入协作开发，查看项目列表。
2. 新建项目，填写名称和描述，添加成员并分配角色；保存后生成项目卡片。
3. 从项目卡片进入“任务清单”，查看该项目全部任务，倒序排列；工作台任务页不被改变。
4. 通过“智能创建任务”进入对话，在对话中选择项目、引用 `task-builder` 技能，确认后生成任务卡。
5. 负责人分派任务，成员执行并提交阶段产物；产物按阶段序号进入任务详情。
6. 审核人查看产物，选择通过或驳回；驳回必须填写原因，任务保留历史提交记录。
7. 项目负责人在详情页维护成员和任务入口；项目详情提供“概览 / 任务”页签，任务页签复用任务模块的列表视图并只显示当前项目的可见任务；产物在任务详情中查看，项目完成后保留只读历史。
8. 研发任务在执行人的 Lingee 桌面客户端本地执行，开始前检查本地开发环境，见下节「本地开发环境」。

历史协作页的任务删除与协作人员移除使用统一确认弹窗；弹窗写明对象及子任务保留、账号不删除等影响，默认聚焦“取消”。

## 本地开发环境

研发任务在执行人的 Lingee 桌面客户端本地执行。**一期只支持 HTTPS，用本机已有凭据或访问令牌授权；浏览器登录（OAuth）待平台授权应用就绪后接入；不提供 SSH。** 账号按人、按平台主机保存；项目目录按人、按电脑保存，与任务执行使用同一目录。

### 设置页

入口为协作开发顶部「设置」页签。灰画布上两张白卡，每行是独立的描边圆角条目。

- **未配置提示**：没有可用的 Git 账号（未登录或全部失效）时，页面顶部显示提示条「未配置 Git 账号，拉取和推送会失败。」和主色「立即配置」，点击打开「添加 Git 账号」；本机未安装 Git 时优先显示安装提示。
- **打开不检测**：只展示上次检测结果（按人保存在本机，只有状态，不含凭据），从未检测过时显示「待检测」。检测只在点「检测」时发起，按钮左侧显示「上次检测 HH:MM」。登录或初始化成功后只重新检测相关平台和项目。
- **Git 账号**：右上角「检测」「＋ 添加账号」（主题色）。列出项目用到的平台、已登录的平台，以及 GitHub、Gitee 公有平台。列为平台（名称 + 主机）、账号（用户名，下方为邮箱 · 来源：来自本机凭据 / 访问令牌；取不到邮箱时只显示来源）、状态、操作（未登录为主色「登录」，已登录为「重新登录」）。
- **我的项目**：标题图标为文件夹。只列本人参与的开发项目：有仓库地址的、Manage 里的研发类空间，以及协作开发自己的项目；Manage 的会议、预算等普通空间不列。有仓库的在前，没配仓库的在后。标题旁用橙色小字显示「N 个项目需要处理」（未初始化，或地址、连通、Git、账号、目录有问题），全部就绪时不显示。列为项目（名称 + 仓库地址）、项目目录（已初始化才显示路径，未初始化显示「—」）、状态、操作（未初始化「初始化」，其余「设置」，均为主色）；SSH 仓库无操作。
- **地址与连通提示**：地址不规范、无法连接、仓库不存在、未配置仓库时，原因直接显示在仓库地址下方（红字，未配置仓库为灰字），并写明谁来改：Manage 空间由能管理该空间的人（负责人、空间管理员、系统管理员）到 Manage「空间设置 › 代码仓库」修改，其他人提示「请联系空间管理员 XX」；协作开发自己的项目找项目负责人。操作列：地址不规范「待修改地址」、未配置仓库「待配置仓库」、无法连接「重新检测」、仓库不存在「更换账号」。
  - **地址不规范**实时判断，不用检测（Manage 新建空间和修改代码仓库时已用同一套规则静态校验，这里兜底校验前录入的地址）：规则见 Manage 文档 07-manager.md（不像地址、仓库网页地址、GitHub / Gitee 地址不完整；GitLab 和其他私有云平台不查段数）。新建空间粘贴地址时用同一套提示。
  - **无法连接 / 仓库不存在**在「检测」和初始化时检查（`git ls-remote`）；初始化前检查不通过时在初始化弹窗里提示，不下载、不改目录。结果保留到下次检测或初始化成功。
  - 这些项目也计入顶部「N 个项目环境未就绪」，浮层里显示原因和对应操作；任务启动时地址不规范直接提示原因，不进入配置对话。
- **新建空间**：「我的项目」右上角「＋ 新建空间」；没有项目时空状态提示「点右上角「新建空间」，粘贴 Git 地址即可创建」。见下文「新建空间」。
- **未初始化不用检测**：项目目录里没有代码即为未初始化，打开设置页就能显示；其余状态来自上次检测。
- **加载失败**：项目清单加载失败时顶部提示「项目加载失败，请重试」并提供「重试」，不显示空列表文案；没有项目时显示「暂无项目」。
- **没有安装 Git**：检测发现没有 Git 时，页面顶部提示「本机没有安装 Git，安装后点「检测」」，并提供「下载 Git」按系统打开官网下载页。Windows 客户端自带 MinGit，一般不会出现。

### 状态

| 状态 | 颜色 | 含义 |
| --- | --- | --- |
| 已就绪 | 绿 | 已登录，代码目录是该项目的 HTTPS 仓库 |
| 未初始化 | 黄 | 本机项目目录里还没有该项目的代码 |
| 未登录 | 橙 | 本机没有该平台的凭据 |
| 凭据失效 | 红 | 平台拒绝了保存的凭据（过期或被撤销） |
| 无权访问 | 橙 | 推送校验（`git push --dry-run`）没通过，按原因提示：令牌没有写权限 → 重新创建令牌并登录；账号在仓库里角色不够（GitLab 需 Developer+、GitHub 需 Write+）→ 显示「待管理员授权」，请项目管理员升角色；GitHub 组织开启 SAML SSO 而令牌未授权 → 到令牌页「Configure SSO › Authorize」后重新登录 |
| 无法连接 | 橙 | 连不上仓库所在平台（网络、代理或未连内网 VPN） |
| 仓库不存在 | 红 | 登录后仍拿不到仓库：地址有误，或账号没有访问权限（平台不区分） |
| 目录不匹配 | 橙 | 绑定目录不是该项目的 HTTPS 仓库 |
| Git 不可用 | 橙 | 本机没有 Git |
| 地址不规范 | 红 | Git 地址格式不对，显示具体原因和正确写法，需由能管理空间的人修改 |
| 未配置仓库 | 灰字 | 项目没有填写代码仓库，需在项目设置中填写 |
| SSH 仓库 | 灰字 | 一期不支持 SSH 地址：提示在 Manage 把代码仓库改成 HTTPS 地址后再登录 Git 账号，操作列显示「待改 HTTPS 地址」 |
| 待检测 | 灰字 | 还没检测过 |

账号状态有可用、即将过期、未登录、凭据失效、无权访问、无法连接、Git 不可用。检测用 `git credential fill`（protocol=https、host=<主机>）查询系统凭据库里是否存了这个主机的凭据，再用该凭据调用平台账号接口验证一次；**不能以 `ls-remote` / `clone` 成功为准**：公开仓库匿名就能读，读成功不代表本机有凭据，推送时照样鉴权失败。推送权限单独用 `GIT_TERMINAL_PROMPT=0 git push --dry-run origin HEAD:refs/heads/_cred-probe` 校验（不会真推送、不建远端分支），在初始化和登录后执行。连不上平台立即停止；验证失败不删除用户已保存的凭据。

令牌到期前 7 天账号状态显示「即将过期」（橙），设置页顶部提示「<主机> 的访问令牌将于 <日期> 到期，到期后拉取和推送会失败」和「重新登录」；执行任务前也会提醒一次，不拦截。凭据是设备级的，每台电脑各自登录一次。

### 登录与添加账号

- 同一个弹窗。从账号行或项目进入时平台已知，标题「登录 Git 账号」，副标题「主机 · 平台」；从「添加账号」进入时标题「添加 Git 账号」，不显示副标题，先单选平台：金蝶 GitLab（默认）/ GitHub / Gitee / 其他 GitLab。前三项自动带出地址（git.kingdee.com、github.com、gitee.com），在选项下方显示「地址：…」；只有「其他 GitLab」需填写平台地址。
- 只有「访问令牌」一项：密码框输入，不提供查看；右侧「去平台创建」在浏览器中打开平台真实的令牌创建页：GitHub、GitLab 通过地址参数预填令牌名称（Lingee）和所需权限（GitLab 较新版本才支持预填），Gitee 只打开页面；下方一行提示「令牌只保存在本机系统钥匙串」。再下方是默认收起的「如何获取访问令牌？」，展开后按所选平台列出步骤：进入令牌页面；勾选所需权限（GitHub：经典令牌 repo，或细粒度令牌 Contents 设为 Read and write；GitLab：read_user、read_repository、write_repository，并选到期时间；Gitee：user_info、projects）；GitHub 组织开启 SSO 时在令牌旁点「Configure SSO › Authorize」；复制令牌（只显示一次）粘贴到上方。GitLab 步骤里带出平台地址。
- 「验证并登录」：令牌经平台账号接口验证后存入系统凭据库（macOS 钥匙串、Windows 凭据管理器），不写入 Lingee 配置文件，不进入对话。失败就近提示：格式不正确、无效或已过期、权限不足、无法连接、系统凭据库不可用。
- 一期没有退出登录，需要时到系统凭据库中删除。

### 初始化项目

- 列表「初始化」打开弹窗，标题「初始化项目」，副标题为项目名。顶部一行「账号：xxx · 主机」与「更换账号」；未登录时显示提示和「登录」，登录后回到本弹窗继续。
- 「项目目录」二选一：**默认目录**（显示路径：工作区目录下的「项目名」文件夹，与任务执行同一目录）或**自定义目录**（未选择时点击打开系统目录选择器，选后显示路径，可「重新选择」）。路径过长时截断，悬停看全文。
- 目录必须在工作区目录内（任务执行只接受这里的目录），不能选 `~/Projects` 等其他位置。
- 主按钮「初始化」：目录里已有该项目的仓库就直接使用，不拉取、不切分支、不改远端；否则在该目录下载代码并检出默认分支，目录里已有的文件保留。目录里是别的仓库、已被其他项目使用、或已有文件与仓库文件同名时失败，原目录和原绑定不变。
- 确认后弹窗关闭，该行按钮显示「初始化中…」，完成后提示并变为「已就绪」，失败用提示条说明原因。项目还没同步到协作后端时，初始化前自动同步。

### 项目设置

与「初始化项目」同一弹窗布局：账号、代码仓库、项目目录（默认目录 / 自定义目录，当前目录不是默认目录时选中自定义并带出路径），另有「打开目录」；标题为「项目设置」，主按钮为「保存」。未就绪时顶部一行说明原因。

- 目录改了才能保存，保存即在新目录按初始化规则完成（已有该仓库直接使用，否则下载代码）；原目录不删除、不改动，原目录里未提交的改动不会带到新目录。
- 原目录下还有任务工作区（进行中的任务）时不允许更改目录，提示等任务完成并封存后再改。
- 项目还没同步到协作后端时不能在这里改目录，到列表点「初始化」。

### 任务自检与智能配置

- （客户端一期未实现，目前由协作后端在任务开始时判断仓库是否就绪）任务开始前检查当前阶段处理人本机环境。本人手动启动且未就绪时进入「本地环境配置」对话或设置页；自动启动或他人触发时任务转为已阻塞并说明原因，由处理人配置后继续。
- 对话一次配置一个项目，登录与目录选择使用上面的共享弹窗；完成后从任务进入的显示「继续执行任务」。

### 新建空间

开始研发项目不用先去 Manage 立项、再回来登录和初始化：在 Build 里新建开发空间，粘贴 Git 地址，一次完成。弹窗格式与 Manage「新建空间」的开发空间（测试研发项目模版）一致。

- **入口**：设置页「我的项目」右上角「＋ 新建空间」（及空状态）；新建任务「所属空间」下拉底部固定的「＋ 新建空间」，建好后自动选中，回到新建任务。对话入口放到二期。
- **权限**：与 Manage「新建空间」一致。正式实现向 Manage 查询当前用户能否新建空间，不能时入口置灰并提示「你没有新建空间的权限，请联系 Manage 管理员」。原型里能进 Manage 的人都能建。
- **弹窗**（标题「新建空间」），字段从上到下：
  1. **空间名称** *：占位「请描述你的空间名称」；没填时，Git 地址检查通过后自动取仓库名。
  2. **空间目标** *：多行，预填「完成研发项目的需求交付与上线」；仍是预填内容时，检查通过后换成仓库描述。
  3. **Git 地址** * 与**基准分支**同一行：分支下拉在检查前为 main / master / develop / 其他，检查通过后换成仓库里的分支并选中默认分支（标「默认分支」）；选「其他」时右侧出现分支名输入框（如 release/2026），按分支命名规则校验，只在出错时提示。Git 地址粘贴后停止输入 0.5 秒、回车或离开输入框时自动检查，结果显示在下方：
     - 格式：与 Manage 共用同一套静态规则（见 07-manager.md）：接受 `https://` 和 `http://`，SSH 地址提示「请填写 HTTPS 地址…SSH 地址暂不支持」。
     - 账号：这个平台没登录时先用本机凭据；没有就提示「还没有登录 <主机> 的 Git 账号」和「登录」，登录后自动重新检查。
     - 连通：正式实现用该账号的凭据跑 `git ls-remote --symref <地址> HEAD`（同时拿到默认分支和分支列表）；能读只说明仓库可读，推送权限另用 `git push --dry-run` 校验，没通过时按上表「无权访问」的三种原因提示，仍可创建。通过时显示「可以访问 · 平台 · 账号 · 默认分支」；连不上时提示确认地址和网络（公司内部平台需连内网或 VPN）；仓库不存在或无权访问时提示确认地址或更换账号；两种都给「重新检查」。能访问但没有推送权限时提示原因，仍可创建，之后更换账号。
     - 已是我的空间：提示「这个仓库已经是空间「X」，将直接使用该空间」，按钮为「使用这个空间」，不重复创建。
  4. **本机目录**：默认目录（工作区目录下的「空间名称」文件夹）或自定义目录（「选择…」工作区目录内的文件夹），校验与初始化相同；已被其他项目使用的目录不能选。
- **创建**：主按钮「创建并初始化」，名称、目标填写、地址检查通过、分支和目录有效时可用。通过 Manage 接口新建开发空间（名称、目标、HTTPS 仓库地址、所选基准分支、平台类型，负责人和成员为本人），再初始化到所选目录；进度在弹窗里显示。完成后提示「已创建「X」，代码在 …」；推送校验不通过时照常创建，提示原因。
- **不在范围**：还没有仓库的空间仍在 Manage 新建；Manage 原有「新建空间」不变。

### 原型边界与演示规则

- 登录、凭据读取、检测、下载和目录选择均为模拟，不访问平台、不修改本机凭据或代码；账号、绑定和检测结果按登录人保存在浏览器本地存储。
- 演示本机凭据为 github.com。令牌少于 8 位为格式错误，含 `expired` / `bad` 为无效，含 `readonly` 模拟令牌没有写权限、含 `norole` 模拟仓库角色不够、GitHub 令牌含 `sso` 模拟未授权组织 SSO（初始化后均为「无权访问」，原因各不相同）；含 `soon` 的令牌 5 天后到期，用于演示到期提醒。公司 GitLab 主机名为 `git.kingdee.com`，旧缓存里按 `gitlab.kingdee.com` 保存的账号会自动迁移。
- 工作区目录演示为 `~/lingeebuild/workspaces/<身份>`；目录选择器返回其中的 `<仓库名>` 文件夹。路径含 `outside` 为工作区外，含 `other` 为别的仓库，含 `used` 为已被其他项目使用，含 `conflict` 为同名文件冲突；原目录路径含 `busy` 视为还有任务工作区。
- 设置页底部「演示：清空本机配置」「演示：模拟未安装 Git」「演示：模拟网络不通」只用于演示；模拟网络不通后点「检测」或初始化，HTTPS 仓库都显示「无法连接」。已有项目的地址含 `offline` 也视为连不上，含 `private` / `missing`（已登录时）视为仓库不存在。
- 新建空间的地址检查为模拟：地址含 `offline` 视为连不上，含 `private` / `missing` 视为不存在或无权访问；`github.com/kingdee/contract-center`、`asset-portal`、`git.kingdee.com/cosmic/hr-onboarding`、`budget-review`、`gitee.com/kingdee/mini-shop` 带演示描述、默认分支和分支列表，其余地址分支为 main、develop。自定义目录「选择…」返回工作区目录下的 `code/<仓库名>`。新建的项目写入 Manage 的本地数据，在 Manage 空间列表可见。

## 状态与异常

- 首次进入协作开发先保留侧栏与顶部页签，HTML 首屏即显示固定居中的 16px 中性灰转圈与「加载中…」短文案，覆盖主脚本下载与业务初始化的完整等待过程，不延迟到模块就绪后再显示；加载期间不显示零数量、空态和未就绪操作。右上角工作区设置图标在身份、工作区权限与目标页签确认后才按原权限显示，加载中保持隐藏，避免先显示再隐藏；顶部导航从 HTML 首屏使用相同字号、间距与高度，不依赖内容面板激活后再切换样式；加载区不切换占位布局、不使用呼吸和进场动效，提示文字固定宽度，重试按钮在下方独立定位，不挤动加载提示；初始化分段执行，数据与首屏就绪后一次展示完整内容；再次进入直接复用数据。
- 加载超过 10 秒提示「加载较慢…」并提供轻量文字按钮「重试」；重试先停止当前初始化再重新执行，避免并发加载。明确失败时显示「加载失败」和「重试」，不刷新整页、不清除本地数据。加载中切页签以最后一次选择为准，离开协作开发后不主动切回。

- 项目：进行中 → 已完成；归档后只读。
- 任务：待开始 → 进行中 → 待审核 → 已完成；驳回回到进行中并保留原因。
- 产物：草稿 → 待审核 → 已通过/已驳回；新版本不覆盖旧版本。
- 成员被移除后不能接收新任务，历史任务和产物仍可查看。
- 保存失败时保留本地旧数据并提示重试，不能生成半条项目或任务关系。

## 用户旅程

管理员或项目负责人进入协作开发 → 新建项目、添加成员和角色 → 成员从任务清单认领任务 → 通过智能创建对话补充任务信息 → 执行并提交带序号产物 → 审核人通过或驳回 → 项目负责人查看完整任务与产物历史并完成项目。
