# 管理

## 目标与范围

管理板块面向经营管理者，对齐产品（kworkuat）把「项目」改为「空间」：用空间组织目标、任务、议题、知识和定时任务。菜单为小灵、空间、AI 组织；空间是本期主体，小灵和 AI 组织为演示页。开发板块仍按「项目」展示这些空间及其研发任务。

## 入口

- 侧栏顶部频道页签：工作 / 管理 / 开发。切到「管理」默认打开空间列表；切回「开发」恢复离开前的开发菜单。
- 管理菜单：小灵、空间、AI 组织；下方「我的空间 · 默认」是小灵会话（「配置全天CEO助理」，点开进入小灵），「空间」目录树与空间列表同口径，点空间名进入空间详情，当前空间高亮。
- 地址：`/manager?m=<菜单>`（`xiaoling`、`ceo-projects`、`organization-management`），空间详情追加 `&proj=<空间 ID>`，刷新后还原；旧地址里不再存在的菜单回到空间列表。

## 数据业务关系

| 对象 | 关键字段 | 关系与规则 |
| --- | --- | --- |
| 空间 | 名称、目标、空间指令、负责人、模板、智能体团队、Git 地址与基准分支（开发空间）、首页板块、里程碑 | 与协作开发的项目分开存放，不出现在开发板块项目列表；开发空间的研发任务在开发板块按项目归属。 |
| 空间成员 | 人员 ID、空间角色（负责人 / 管理员 / 成员）、岗位（产品 / 开发 / 测试） | 人员与开发板块共用；岗位用于研发任务审核人默认匹配。 |
| 空间智能体 | 智能体 ID、功能权限（对话调用 / 读取空间知识库 / 写入任务产物） | 在「成员与权限」右栏装配，来源为智能体中心。 |
| 空间任务 | 编号、处理人、进度、优先级、状态、执行计划 | 通用任务只在管理板块；研发任务写入开发板块任务数据，当前处理人为当前阶段执行人，在开发板块「任务」中处理，进展回到空间详情。 |
| 议题 | 标题、来源、状态、关联任务、决策记录 | 任务行「升级为议题」生成；风险议题关联被阻塞的任务，由空间负责人、空间管理员或系统管理员批准 / 驳回。 |
| 空间知识库 | 文件 ID、名称、所属文件夹、类型、标签、是否向量化、可见范围 | 任务产物归档后进入；会议纪要是默认文件夹。 |
| 定时任务 | 名称、提示词、执行计划、产物归档目录、启停 | 每个空间默认一条「空间最新进展总结」（每周一 08:00，暂停）；执行记录保存在本地。 |

## 关键流程

1. 空间列表：标题「空间」，右侧搜索（按空间名或负责人过滤）和「新建空间」；卡片栅格展示空间名、目标（两行截断）、负责人头像与姓名，点卡片进入详情。暂时只展示开发类空间和用户自己新建的空间，按最近修改时间倒序。底部对话框「您可以通过对话来创建任务，快来试试吧」，带「专家」「选择空间」两个胶囊；选好空间后发送，进入该空间并打开带入内容的新建任务弹窗（第一句作任务名、全文作描述，开发空间为新建研发任务并预选空间的智能体团队）；未选空间时提示先选择。
2. 新建空间：模板单选为空白、管理例会、预算目标、人才布局、协作开发，选中项为品牌浅底；通用模板填空间名称、「目标 / 空间指令」页签（目标必填，模板带默认目标）和智能体团队（「＋ 添加」从智能体团队里选，可移除）；「协作开发」是开发空间，填空间名称、空间目标（预填「完成研发项目的需求交付与上线」）和 Git 地址 + 基准分支（main / master / develop / 其他）。底部「取消」「确定」；负责人默认当前登录用户，成员在空间详情里邀请。
3. 空间详情：左上「‹ 空间详情」返回列表；标题右侧「邀请成员」、成员与权限、空间设置、「···」（重命名、删除空间）。主栏按首页板块显示页签（开发空间默认「研发任务」「动态」），右上可收起右栏。右栏四张卡：议题（有待处理时显示数量）、空间概览（目标与负责人；仓库及基准分支仅在设置页的研发任务齿轮弹窗维护）、知识库（带上传图标）、定时任务（数量与前 3 条的名称、执行计划），点卡片进入对应子页面。底部对话框在当前空间创建任务，宽度上限 560px，右下提供语音占位入口与发送；语音尚未接入，仅提示改用文字输入。
4. 研发任务：表头为编号、任务名（标题 + 描述一行）、处理人、进度（进度条 + 已完成阶段 / 总阶段）、优先级、状态；状态筛选为全部、草稿、待开始、进行中、待审核、已完成、已阻塞、已取消（带数量），搜索编号或任务名；不设行操作和「新建任务」按钮，新任务通过底部对话创建。点行在右侧滑出开发板块同款任务详情（只读，轮到自己的阶段保留「在开发页签处理」）。「计划与任务」与「动态」沿用原有列表、里程碑、甘特图与活动流。
5. 子页面（左上箭头返回空间详情）：
   - 议题：页签「待处理 / 处理中 / 已处理」带数量，右上「对话创建」（演示）；有权限的人可批准 / 驳回，「查看任务」回到详情并打开该任务。
   - 空间概览：空间目标卡、代码仓库卡（开发空间才有：Git 地址、基准分支）、里程碑卡（已完成 x/y，按日期判断完成）。
   - 知识库：页签「空间知识 / 个人知识」，提示条说明默认文件夹与授权；「空间知识库」卡片带新建文件夹、本地上传、引用企业知识（演示），按文件夹筛选、按名称 / 标签检索；表格列为 #、文件 ID、名称、所属文件夹、类型、标签、是否向量化、可见范围、操作。
   - 定时任务：页签「定时任务 / 执行记录」，右上数据范围「空间数据」、搜索和「＋ 新任务」；列表列为任务名称、创建人、执行计划、启停开关、运行状态（运行中 / 已暂停）、操作（立即执行写入执行记录、删除）。
   - 添加定时任务：提示「后台自动运行，含人工确认的流程会自动终止」；任务名称、提示词（附件 / 选择智能体 / 模型为演示）、执行计划（单次、固定间隔、每小时、每天、每周、每月）、计划日期与时间、产物归档目录必填项校验，右上「取消」「确认创建」。
6. 成员与权限：左右两栏。左栏成员：搜索、页签「全部 / 负责人 / 管理员 / 成员 / 参与人」带人数、每页 6 人分页，管理员和成员可改空间角色、岗位或移除（二次确认）；「邀请」打开邀请成员弹窗（空间管理员 / 成员）。右栏智能体：搜索、「点开智能体可查看并设置其功能权限」，点开后勾选对话调用、读取空间知识库、写入任务产物，或移除；「＋ 添加」打开「添加空间智能体」弹窗（智能体中心 · AI 组织，可搜索、多选，确定后装配）。仅空间负责人、空间管理员或系统管理员可维护。
7. 空间设置（「‹ 空间设置」返回详情）：目标卡（空间目标，超过三行折叠）、空间首页板块显示设置卡、空间指令卡（空时提示「还未配置空间指令，点右上角「编辑」补一条。」），研发任务行尾齿轮打开「研发协作设置」，填写 Git 地址与基准分支，取消不保存、确定校验后保存；不再单独展示代码仓库卡；各卡「编辑」后就地修改、保存或取消。首页板块查看态列出显示中的板块（序号 + 名称 + 模板 / MCP / 知识标签）；编辑态有预置模板（管理例会、预算目标、人才布局、协作开发，点选即覆盖当前组合）、每行拖动手柄（键盘 Alt + ↑↓ 调序）和显示开关、添加的板块可删除、「＋ 添加板块」菜单（MCP：挂载一个 MCP App；项目知识库：展示一份知识文件），至少保留一个显示的板块，「保存」后同步详情页签。
8. 重命名 / 删除空间：「···」→「重命名」（必填、不超过 60 字、不重名，同步标题、卡片和侧栏目录树）；「删除空间」二次确认后连同任务和议题删除，返回列表。
9. 小灵：顶部「小灵」标识，对话区预置自我介绍，输入「输入消息，与管理助理对话...」发送后给出演示回复；右上按钮展开右侧议题中心（待处理数量）、审批中心（暂无待审批单据、AI 授权）、态势三张卡，点击提示不在演示范围。
10. AI 组织：概况卡（智能体数量、进行中与待审核的研发任务数）和「AI 部门运营概览」卡片栅格（部门名、负责人、运行正常、职责描述、智能体数、本月任务），「创建 AI 部门」为演示提示。

## 状态与异常

- 空间名称、目标、开发空间 Git 地址必填，就近提示并不保存；基准分支名不合法时提示原因。
- Git 地址只做静态格式校验（Manage 所在环境可能连不上代码平台），新建空间时离开输入框即提示、点「确定」再校验一次，「空间设置 › 代码仓库」保存时同样校验：只接受 `https://` 和 `http://` 地址（内网平台可能没配证书，SSH 暂不支持）；末尾带不带 `.git` 都可以。只拦格式上能确定的问题，宁可放过也不误报：不像地址（如「git」、带空格）；含 `/-/` 的 GitLab 网页地址；GitHub、Gitee（主机名含 github / gitee）路径必须正好「用户名或组织/仓库名」两段，多出来的（如 `…/tree/main`）是网页地址，少一段不完整。GitLab 和其他私有云平台路径规则不一，不查段数，只查前两条。出错时给出原因和正确写法。能否连通由 Build 客户端在检测和初始化时检查。规则与 Build 共用（`core/git-url.js`）；校验前录入的历史地址在 Build 设置页显示为「地址不规范」。
- 研发任务未选智能体团队、无有效阶段时不保存。
- 空间成员与智能体、空间设置、定时任务新增 / 删除仅空间负责人、空间管理员或系统管理员可操作，其他人只读；有未完成任务的成员不能移除；空间至少保留 1 名成员。
- 本地存储不可用时提示保存失败，不写入半条数据。

## 原型边界

空间、任务、议题、定时任务与执行记录保存在浏览器本地；底部对话创建任务以打开新建任务弹窗模拟 AI 拆解；知识库上传、引用企业知识、MCP 板块内容、小灵回复、审批中心与 AI 组织数据均为演示；代码分支的拉取与合并只做状态展示。

## 演示数据：工单管理系统（CIO）

「工单管理系统」由空间管理员赵琳创建（4 周：9 月 21 日至 10 月 16 日），交付智能体团队为通用应用开发智能体团队，仓库 `helpdesk`，基准分支 main。22 个研发任务 T1001600–T1001621：18 个已完成（进度 82%）、2 个待审核、1 个待开始、1 个已阻塞（「工单自动派单算法」卡在调度集群扩容审批，对应一条待处理的风险议题）；知识库已归档 4 份产物。另有「客户门户改造」「采购协同应用」两个开发空间使用同一支智能体团队，用来体现组织级复用。CIO 视角演示脚本见 `docs/CIO演示脚本-工单管理系统.md`。

## 演示数据：设备巡检维修

「设备巡检维修系统建设」是 Manage 里的开发空间（负责人张工，周期 10 月 8 日至 23 日，半个月交付；智能体团队为苍穹应用开发智能体团队，空间智能体为苍穹产品、元数据、质量三个智能体，知识库归档了故障报修需求的需求规格、元数据清单和测试报告，仓库 `equipment-ops`，基准分支 main），是汇报 6.1 / 6.2 的贯穿空间。项目下的研发任务 T1001500–T1001506 在开发板块「协作开发 → 任务」里处理，任务详情显示所属项目（开发板块仍按项目展示空间）；协作开发不再有项目页签。

## 下拉选择

普通单选字段复用共享下拉组件，统一箭头、面板、选中标记与单边框焦点状态；支持键盘选择、禁用项和空值选项（如「全部」或「无」）。现有搜索、多选选择器保留原有能力，归档页面不迁移。

管理首页对照 UAT：侧栏未产生管理任务时显示「暂无任务」，不再展示预置的 CEO 助理会话；小灵首次进入展示头像、三项能力介绍和「立即启用」，点击后进入现有管理助理演示对话；启用状态仅在本次页面会话内保留，不授予真实代理权限。空间列表使用三列白卡、两行摘要和负责人，窄窗口降为两列／单列；摘要不直接显示 Markdown 粗体与标题标记。新建空间沿用目标／指令和团队选择、协作开发 Git 配置与校验，弹窗主体滚动，底部操作保持可达。
