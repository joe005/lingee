# 智能体与智能体团队

## 目标与分层

协作空间提供可使用的智能体（智能体）和智能体团队。列表按来源分为：**金蝶官方**、**企业自建**、**个人开发**；来源决定可编辑范围和安装方式。

开发侧栏的资产管理入口统一命名为「企业资产」「原厂资产」，名称右侧以箭头表示云端入口，分别用于本企业与金蝶官方的开发智能体、智能体团队管理；与工作板块的「企业控制台」区分。当前原型沿用已有管理预览页与权限规则。

- 金蝶官方：平台发布，客户端只读使用；发现新版本时卡片直接提示更新。
- 企业自建：由租户审核发布，租户成员可安装和更新。
- 个人开发：当前用户创建和编辑的草稿；提交审核后生成企业自建资产，个人稿仍保留，二者可并存。

## 数据业务关系

| 对象 | 关键字段 | 规则 |
| --- | --- | --- |
| 智能体 | `assetId`、类型、来源、`tenantId`、名称、简介、头像 | 官方内容不绑定租户；企业自建必须绑定一个 `tenantId`；个人开发绑定创建人。 |
| 智能体团队 | `assetId`、来源、`tenantId`、成员快照、组长、阶段绑定 | 每个阶段可绑定一个或多个智能体；发布时固定成员与阶段绑定的资产版本，成员单独更新不会改变已安装团队。 |
| 版本 | `versionId`、`assetId`、版本号、快照、更新说明 | 版本号自动递增且只读；版本快照不可修改。 |
| 本地安装 | `assetId`、安装版本、安装来源、安装时间 | 同一来源资产可安装多个版本，但客户端只启用一个当前版本。 |
| 审核提交 | `reviewId`、快照、提交人、目标租户、状态、原因 | 审核针对提交快照，不直接锁定个人草稿。 |

平台、租户和本地安装分别使用独立存储键；正式服务以资产 ID、租户 ID 和版本 ID 做唯一约束。

## 角色与权限

| 能力 | 普通成员 | 个人开发者 | 租户管理员 | 原厂管理员 |
| --- | --- | --- | --- | --- |
| 查看/安装官方资产 | 可 | 可 | 可 | 可 |
| 创建和编辑个人开发资产 | 可 | 本人可 | 可 | 可 |
| 提交企业审核 | 本人可 | 本人可 | 可 | 可 |
| 审核企业内容 | 无 | 无 | 仅本租户 | 原厂内容 |
| 发布/下架企业资产 | 无 | 无 | 本租户 | 官方资产 |
| 编辑已发布官方资产 | 无 | 无 | 无 | 可 |
| 查看历史版本/导出 ZIP | 已安装范围 | 本人范围 | 本租户 | 官方范围 |

预置/官方卡片不显示编辑和“复制为个人”；个人开发卡片先打开详情，点击“编辑”才进入 `expert-builder` 对话和统一侧栏。

## 客户端流程

- 删除个人开发的智能体或智能体团队时使用统一确认弹窗，写明对象和不可撤销的影响；删除智能体若会影响团队成员，还要显示受影响的团队数量，默认聚焦“取消”。
- 智能体和智能体团队页签共享搜索、来源筛选、胶囊式新增按钮和卡片布局；“我的”列表按“个人开发”“我添加的”分组，空分组隐藏，搜索与来源筛选同时作用于两组。“更多”只展示尚未安装的可用云端资产，已安装内容在“我的”中查看。
- 列表按 Figma 的三列白卡布局展示，窄窗口降为两列或单列；标题下展示来源、已安装版本及技能／成员数量，简介最多两行，升级提示以图标保留在卡片右下方，悬停提示目标版本，点击打开更新说明。团队头像超过 4 人时展示 3 人及剩余数量。详情使用 720×640 的居中弹窗，超出视口时缩小，正文独立滚动；对话内编辑面板保留原布局。
- 云端智能体和智能体团队默认按最近修改时间倒序排列，搜索和来源筛选沿用当前排序。
- 卡片悬停或键盘聚焦显示“更多”和对话图标；更多菜单可查看详情，个人资产保留删除确认入口，已安装的官方／企业资产另提供“卸载”。菜单支持方向键、Home / End、Esc 和点击外部收起。
- 卸载需确认，从“我的”列表移除后可在“更多”中重新安装；保留云端版本、个人配置及会话历史。智能体仍被已安装或个人团队引用时阻止卸载，卸载团队保留其成员；确认前后均检查引用，存储失败保留原安装状态。更新设置只针对已安装内容，不会重新安装已卸载资产。
- “更多”中未安装资产显示“+”；点击后校验并安装依赖，成功后提示“已添加智能体 / 智能体团队”并回到“我的”列表。升级图标打开 460px 弹窗，左右展示当前与目标版本、更新说明和依赖成员；安装完成、无法卸载使用同宽信息提示弹窗，无法卸载时列出引用团队。
- 安装智能体团队时自动补齐缺失的企业智能体成员；任一依赖安装失败则整体回滚并保留旧版。
- 已安装资产发现更高版本时直接在卡片显示“有更新”，打开更新说明后可更新全部。
- 更新失败保留旧版本、个人配置和会话历史。
- 升级演示：软件产品经理、软件架构师、通用应用需求设计智能体、苍穹产品经理、通用应用开发智能体以及苍穹／通用应用开发团队提供 1.0.0 → 1.1.0 示例，包含更新说明；团队升级同时列出需更新的成员。仅为未人工修改的初始资产补充云端版本，不重置已安装版本或恢复已卸载资产。
- 开发侧栏新增「技能·智能体·连接器」菜单，按页签展示「技能 / 智能体 / 智能体团队 / 连接器」，默认进入技能页，页签间可互相切换。智能体、智能体团队沿用协作开发的现有列表（协作开发里的页签保持不变），页签只作导航；技能页与智能体页同一目录维度：「我的技能」分「我开发的」（个人开发，含已发布／待提交状态）和「我安装的」（金蝶官方、企业自建），「我的技能」顶部有与「我的智能体」一致的来源筛选（全部／金蝶官方／企业自建／个人开发，带数量），卡片沿用智能体卡片结构（圆形头像、来源与版本描边标签、简介、底部标签）；「更多技能」列出未安装的金蝶官方与企业自建技能，点「+」安装后进入「我安装的」，已安装技能悬停出现「卸载」并需确认（技能为演示数据，状态仅本页生效，原「技能开发」页不变）；连接器页上方是各类系统的连接器卡片（腾讯云、阿里云、华为云、金蝶AI 星瀚、金蝶AI 星空，即对话「＋ → 连接器」里的同一批，卡片标注“通过 MCP 接入”，支持搜索和连接／断开演示），下方是接入它们的「MCP 服务器」列表（页头有刷新、添加 MCP；每行为名称与连接状态、查看配置、编辑和启用开关，启用后演示“连接中 → 已连接”）；卡片与服务器均为演示数据，状态只在本页生效、不与对话输入框联动。原「技能开发」「智能体开发」菜单和协作开发页签保持不变；刷新后仅技能页与连接器页会保留页签导航，其余回到原页面。

## 创建、导入与提交

1. 点击“新增”进入对话，引用 `expert-builder`；创建智能体团队时根据职责描述推荐匹配的智能体，以 AskUserQuestion 风格多选确认后生成结果卡片；点击卡片打开详情，个人开发详情点击“编辑”才进入右侧对话配置；智能体和智能体团队的个人开发详情在名称行提供“编辑 / 发起对话”，概览的审核状态区提供“提交审核”，无需进入编辑即可提交；不再选择企业，直接提交给当前所在企业，填写 100 字以内的必填提交说明后关闭提交和详情弹窗，顶部提示“提交成功”，并说明待企业管理员审核、个人版本仍可使用。
2. 导入 ZIP 仅模拟解析和扫描，不读取实际文件；确认头像、名称、简介后保存为草稿。
3. 新资产直接保存草稿；已存在资产要求填写更新说明并自动生成下一个只读版本。
4. 编辑页提交审核；企业自建目标由当前租户确定，个人开发稿仍可继续编辑。
5. 审核通过后上架；驳回时才显示必填原因。驳回不生成可安装版本。
6. 侧栏「智能体开发」页对齐 Lingee Build：悬停卡片显示「⋯」菜单（编辑、本地测试、云端测试、提交、删除）；仅「已保存」「已驳回」的智能体有「提交」，确认「提交上架审核」后提示“提交成功，请等待管理员审核”，卡片状态变为「已提交」。其余菜单项为提示占位。
7. 点击「智能体开发」卡片打开智能体开发会话：左侧是 agent-builder 的交付摘要和智能体卡片，右侧是智能体配置面板，右上角为保存、测试（本地测试 / 云端测试）、提交。基础信息含模型策略和更新日志（每条为「时间 · 人 + 变更内容」，如新增技能、知识范围调整）；角色设定为可编辑正文；技能配置平铺技能卡片（「本地技能 | 已发布」，描述写明数据来自哪个系统、只读不改）；知识页左侧为「关联企业知识」和「上传知识 → 临时目录」，右侧为所选目录的文件卡片，「上传」后文件进入临时目录，支持按目录、文件名或创建者搜索。「测试」另开独立测试会话：标题「测试 · 智能体名」，云端测试带「Console沙箱」标记，输入框带智能体标签，提示测试不触碰生产数据；回答显示调用的技能。从协作开发任务里测试时先收起任务详情，「返回主会话」回到协作开发，任务产物里的配置（如已上传的知识）保留。提交复用「提交上架审核」确认（强调这是生产环境操作，管理员审核通过后生效），完成后面板和卡片状态都变为「已提交」，提交按钮禁用；从协作开发任务里提交时，交付它的任务同步完成。完整演示数据有「设备故障诊断助手」和「销售履约智能体」，面板的基础信息、角色设定、技能和关联知识目录按智能体切换；测试回来再打开面板时，保留已上传的知识和更新日志。
8. 开发板块「新会话」首页选「智能体开发」（输入框出现 agent-builder 标签），用大白话说出设备排障经验，并要求同时创建「查询设备档案」「查询维修记录」两个技能，发送后进入「创建设备故障诊断助手」会话。过程对齐 Lingee Build 的 agent-builder 会话（界面显示名同 Build：agent-builder、skill-builder）：「运行中...」下逐条出现过程说明和工具行，agent-builder 调用 skill-builder 随助手一起生成两个技能（并行写入 SKILL.md、manifest.yaml、CHANGELOG.md 并校验），再写入角色、初始化智能体并自动绑定这两个技能、关联企业知识目录、严格校验，完成后收起为「处理完成 > 1分42秒」，给出交付摘要（智能体配置 / 角色定位 / 技能创建与绑定 / 知识库关联）和智能体卡片。点卡片打开右侧配置面板（知识页默认显示关联的企业知识目录）；卡片上「本地测试」另开测试会话，回答前依次显示查询设备档案、查询维修记录、对照经验；「返回主会话」回到创建会话。面板「提交」确认后模拟企业审核通过，面板和卡片状态变为「已发布」。
9. 同一入口说出销售履约的需求和规矩（含“销售履约”“接单”“催收”等词）时，进入「创建销售履约智能体」会话（演示账号林悦，商务主管）：agent-builder 调用 skill-builder 生成并绑定「接单制单」「履约执行」「收款催收」「销售月报」四个技能，经 MCP 连接金蝶 ERP（读客户信用、应收与收款，写销售订单、发货通知、运单、销售出库，写操作先存草稿），关联「销售履约知识库」，交付摘要另列「金蝶 ERP 连接」和待上传的运价表、催收函模板、网页报告模板。本地测试会话提示里可「附上示例采购单」，发送后依次显示解析采购单、查询客户信用、创建销售订单（暂存）、生成网页预览，回答含信用检查表、订单草稿和可点开的订单网页预览，最后询问是否提交审核；提交后模拟企业审核通过，发布给销售团队。

## 工作模式：使用智能体

侧栏顶部切到「工作」时，开发导航和开发视图隐藏，显示工作导航（新任务、定时任务、智能体、技能、发现、历史对话）和对话页；切回「开发」恢复原样。对话页输入框里的智能体选择器可选已发布或已提交的智能体，发送后先显示「深度思考中」，再给出「任务完成 · 调用 N 个技能（经 MCP 读取的系统）」、回答和参考来源（维修记录、内置知识）。「设备故障诊断助手」被问到注塑机温度问题时，先引用维修记录，再按老师傅的经验给出排查步骤；其它智能体和导航项为提示占位，回答均为本地模拟。

## 智能体团队发布规则

- 成员必须引用已发布或待发布的智能体版本，且组长必须是成员。
- 发布时写入成员版本快照；后续成员更新需重新提交智能体团队版本。
- 开发流程的每个阶段展示绑定的智能体，一般 1 位、最多 2 位；未手动绑定时按智能体的「能力项」匹配（阶段看重的能力项 + 成员在这些能力上的等级，第二位须与第一位相当才入选），手动绑定超过 2 位时提示先取消一位；没有任何成员匹配的阶段显示「能力待补齐」。
- 两支内置团队使用固定交付范围：通用应用开发为需求分析、系统设计、开发实现、测试验证；苍穹应用开发为需求分析、开发实现、测试验证（后者阶段描述为空）。具体 WorkItem 由 Runtime 在阶段内动态生成；智能体、技能与业务组件开发属于开发阶段内的工作，不单独增加交付阶段。交付路径只有「功能开发」和「缺陷修复」：需求取团队的交付范围（通用团队需求分析、系统设计、开发实现、测试验证 4 个阶段，苍穹团队 3 个阶段，自建团队默认 4 个阶段），任务类型为「缺陷」的任务无论内置还是自建团队都只有开发实现、测试验证 2 个阶段；不再有「方案咨询」，也没有可选的智能体开发阶段。已缓存的缺陷任务一次性迁移到这 2 个阶段，旧阶段并入相邻阶段并保留状态与产物。
- 内置智能体及苍穹应用开发、通用应用开发两支团队，以 `/Users/wuhc/Projects/lingee-build/packages/opencode/builtin-experts` 的定义为准，名称、说明、标签、工作模式、技能中文元数据及团队成员同步该工程。独立列表同时遵循 `packages/kcode-web/src/utils/expert-visibility.ts`：禁用定义不展示；团队负责人、创建助手及仅供团队调用的专业智能体不单独展示，但保留内部 ID、技能与成员引用。默认展示 8 个内置智能体、2 支团队，用户自建内容另计；苍穹产品、苍穹应用开发、苍穹质量优先排列。
- 智能体详情的「概览」页签与 Lingee Build 客户端一致：简介、标签、常见触发词（单行文字，点击带着该智能体开启新会话）；不再展示能力项和模型级别（能力项只用于团队阶段匹配和创建 / 编辑，创建 / 编辑智能体时「可承担的工作」仍保留）。
- 原型预置的内置智能体和团队不再附带租户示例（业务需求、交付实施、企业交付团队）和云端示例（交付顾问）；企业自建、个人开发列表只显示用户自己创建或共享的内容。
- 智能体团队详情只保留「概览 / 开发流程」两项页签；概览展示名称行、说明、个人资产审核状态、触发词和双列成员卡片；两支内置团队的说明取自各自 `domain-pack.json` 的中文描述；「组长」标记在概览与编辑时均显示，编辑时可设置组长。
- 智能体团队详情与编辑的「开发流程」页签顶部是路径切换标签（功能开发、缺陷修复，每个标签带阶段数），默认只展示功能开发，点标签切换，每次打开详情都回到功能开发；功能开发显示团队的交付范围，缺陷修复固定显示开发实现、测试验证两个阶段；每条路径的阶段按纵向时间线从上到下排列（左侧圆点加竖线串起各阶段，不显示序号），每个阶段的名称和说明下方展示该阶段绑定的智能体，阶段标题同行显示「AI 智能体执行」标签，成员以无外框的灰色头像胶囊列在说明下方，说明该阶段由 AI 智能体而不是真人在干活（未绑定智能体时不显示），成员胶囊放不下时换行；居中详情弹窗不显示测试按钮，保存和测试在对话侧栏的编辑区右上角，个人资产的提交审核还可从详情概览进入。
- 下架被已上架智能体团队引用的智能体时，提示引用关系并阻止下架；无真实引用时允许下架，历史版本保留。

## 状态机

草稿 → 待审核 → 已上架 → 已下架；待审核可驳回，驳回回到草稿。已上架产生更新时进入新的草稿/待审核链路，旧上架版本持续可用。

## 用户旅程

个人开发者新增智能体 → 对话生成并编辑 → 提交企业审核 → 租户管理员查看快照并通过/驳回 → 通过后进入更多智能体 → 成员点击“+”安装 → 发现新版本时查看更新说明并整体更新。创建智能体团队时选择成员版本 → 安装团队自动补齐依赖 → 团队固定使用成员快照。

## 原型边界

云端目录、扫描、审核、安装、更新和依赖补齐均为浏览器本地持久化模拟；不代表真实云端分发、包安全扫描或跨设备同步。

## 智能体详情知识布局

详情标题固定为“智能体详情”，名称、头像和来源放在概览正文；概览、技能、知识采用 40px 高的胶囊分段页签，选项 32px 高，支持方向键切换。知识页顶部是企业知识、上传和搜索，下面共用一个圆角外框，左侧 192px 目录区与右侧文件区以竖线分隔，分别滚动；点击父目录展示子目录与文件，点击子目录同步高亮与路径，搜索按目录、文件名及创建者匹配。无修改时隐藏知识底部操作，修改关联、上传或检索范围后显示取消和保存，保存后收起。

## 下拉选择

普通单选字段复用共享下拉组件，统一箭头、面板、选中标记与单边框焦点状态；支持键盘选择、禁用项和空值选项（如「全部」或「无」）。现有搜索、多选选择器保留原有能力，归档页面不迁移。

## 截图还原的详情与选择器

智能体概览的说明、审核状态、标签与触发词按纵向排列；官方资产显示概览、技能、知识，个人资产显示概览、技能。技能采用双列白色描边卡片，每张展示彩色首字图标、技能名和两行简介。团队成员采用双列卡片，展示头像、姓名、组长标签和职责。列表、详情中的名称、版本和人员使用现有数据，不以截图中的示例覆盖。

新会话的智能体选择器宽 220px，先团队后智能体，中间用分隔线，个人团队显示“本地”；搜索可清空，输入关键词后隐藏底部管理入口，保留选中与跳转管理能力。

## 开发会话执行对象选择

新会话与对话输入区的「＋」菜单依次提供「上传附件或图片」「智能体团队」「引用文件夹」「知识库」，其后保留模式与连接器。「智能体团队」展开共用的智能体／团队选择列表；两支内置开发团队统一命名为「苍穹应用开发团队」「通用应用开发团队」，列表卡片、详情及选择器使用同一名称，以便与单个开发智能体区分；已有未人工修改的内置资产缓存随定义同步名称。选中行使用品牌浅紫底、品牌文字与勾选标记；输入区同步显示所选智能体头像或团队成员组合头像及名称，悬停保留选中底色。名称右侧只保留一个操作位置：默认显示下拉箭头，悬停或键盘聚焦标签时替换为清除按钮；展开选择器时显示向上箭头。点击名称打开选择器，点击清除不展开选择器，图标切换不改变标签宽度。清除后标签隐藏，可重新从「＋」选择；已开始会话沿用执行对象锁定规则。
