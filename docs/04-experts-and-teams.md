# 智能体与智能体团队

## 目标与分层

协作空间提供可使用的智能体（专家）和智能体团队。列表按来源分为：**金蝶官方**、**企业自建**、**个人开发**；来源决定可编辑范围和安装方式。

- 金蝶官方：平台发布，客户端只读使用；发现新版本时卡片直接提示更新。
- 企业自建：由租户审核发布，租户成员可安装和更新。
- 个人开发：当前用户创建和编辑的草稿；提交审核后生成企业自建资产，个人稿仍保留，二者可并存。

## 数据业务关系

| 对象 | 关键字段 | 规则 |
| --- | --- | --- |
| 智能体 | `assetId`、类型、来源、`tenantId`、名称、简介、头像 | 官方内容不绑定租户；企业自建必须绑定一个 `tenantId`；个人开发绑定创建人。 |
| 智能体团队 | `assetId`、来源、`tenantId`、成员快照、组长、阶段绑定 | 每个阶段可绑定一个或多个智能体；发布时固定成员与阶段绑定的资产版本，成员单独更新不会改变已安装团队。 |
| 版本 | `versionId`、`assetId`、版本号、快照、更新说明 | 版本号自动递增且只读；版本快照不可修改。 |
| 本地安装 | `assetId`、安装版本、安装来源、安装时间 | 同一来源资产可安装多个版本，但客户端只启用一个当前版本。 |
| 审核提交 | `reviewId`、快照、提交人、目标租户、状态、原因 | 审核针对提交快照，不直接锁定个人草稿。 |

平台、租户和本地安装分别使用独立存储键；正式服务以资产 ID、租户 ID 和版本 ID 做唯一约束。

## 角色与权限

| 能力 | 普通成员 | 个人开发者 | 租户管理员 | 原厂管理员 |
| --- | --- | --- | --- | --- |
| 查看/安装官方资产 | 可 | 可 | 可 | 可 |
| 创建和编辑个人开发资产 | 可 | 本人可 | 可 | 可 |
| 提交企业审核 | 本人可 | 本人可 | 可 | 可 |
| 审核企业内容 | 无 | 无 | 仅本租户 | 原厂内容 |
| 发布/下架企业资产 | 无 | 无 | 本租户 | 官方资产 |
| 编辑已发布官方资产 | 无 | 无 | 无 | 可 |
| 查看历史版本/导出 ZIP | 已安装范围 | 本人范围 | 本租户 | 官方范围 |

预置/官方卡片不显示编辑和“复制为个人”；个人开发卡片先打开详情，点击“编辑”才进入 `expert-builder` 对话和统一侧栏。

## 客户端流程

- 智能体和智能体团队页签共享搜索、来源筛选、胶囊式新增按钮和卡片布局。
- 云端智能体和智能体团队默认按最近修改时间倒序排列，搜索和来源筛选沿用当前排序。
- 未安装企业资产显示“+”；点击安装时先校验依赖。
- 安装智能体团队时自动补齐缺失的企业智能体成员；任一依赖安装失败则整体回滚并保留旧版。
- 已安装资产发现更高版本时直接在卡片显示“有更新”，打开更新说明后可更新全部。
- 更新失败保留旧版本、个人配置和会话历史。

## 创建、导入与提交

1. 点击“新增”进入对话，引用 `expert-builder`；创建智能体团队时根据职责描述推荐匹配的智能体，以 AskUserQuestion 风格多选确认后生成结果卡片；点击卡片打开详情，个人开发详情点击“编辑”才进入右侧对话配置；智能体和智能体团队的个人开发详情另有“提交审核”（均在底部，与“删除”“取消”“编辑”同一排），无需进入编辑即可提交；不再选择企业，直接提交给当前所在企业，填写提交说明后提示“提交成功，待企业管理员审核”。
2. 导入 ZIP 仅模拟解析和扫描，不读取实际文件；确认头像、名称、简介后保存为草稿。
3. 新资产直接保存草稿；已存在资产要求填写更新说明并自动生成下一个只读版本。
4. 编辑页提交审核；企业自建目标由当前租户确定，个人开发稿仍可继续编辑。
5. 审核通过后上架；驳回时才显示必填原因。驳回不生成可安装版本。
6. 侧栏「智能体开发」页对齐 Lingee Build：悬停卡片显示「⋯」菜单（编辑、本地测试、云端测试、提交、删除）；仅「已保存」「已驳回」的智能体有「提交」，确认「提交上架审核」后提示“提交成功，请等待管理员审核”，卡片状态变为「已提交」。其余菜单项为提示占位。
7. 点击「智能体开发」卡片打开智能体开发会话：左侧是 agent-builder 的交付摘要和智能体卡片，右侧是智能体配置面板，右上角为保存、测试（本地测试 / 云端测试）、提交。基础信息含模型策略和更新日志（每条为「时间 · 人 + 变更内容」，如新增技能、知识范围调整）；角色设定为可编辑正文；技能配置平铺技能卡片（「本地技能 | 已发布」，描述写明数据来自哪个系统、只读不改）；知识页左侧为「关联企业知识」和「上传知识 → 临时目录」，右侧为所选目录的文件卡片，「上传」后文件进入临时目录，支持按目录、文件名或创建者搜索。「测试」另开独立测试会话：标题「测试 · 智能体名」，云端测试带「Console沙箱」标记，输入框带智能体标签，提示测试不触碰生产数据；回答显示调用的技能。从协作开发任务里测试时先收起任务详情，「返回主会话」回到协作开发，任务产物里的配置（如已上传的知识）保留。提交复用「提交上架审核」确认（强调这是生产环境操作，管理员审核通过后生效），完成后面板和卡片状态都变为「已提交」，提交按钮禁用；从协作开发任务里提交时，交付它的任务同步完成。完整演示数据有「设备故障诊断助手」和「销售履约智能体」，面板的基础信息、角色设定、技能和关联知识目录按智能体切换；测试回来再打开面板时，保留已上传的知识和更新日志。
8. 开发板块「新会话」首页选「智能体开发」（输入框出现 agent-builder 标签），用大白话说出设备排障经验，并要求同时创建「查询设备档案」「查询维修记录」两个技能，发送后进入「创建设备故障诊断助手」会话。过程对齐 Lingee Build 的 agent-builder 会话（界面显示名同 Build：agent-builder、skill-builder）：「运行中...」下逐条出现过程说明和工具行，agent-builder 调用 skill-builder 随助手一起生成两个技能（并行写入 SKILL.md、manifest.yaml、CHANGELOG.md 并校验），再写入角色、初始化智能体并自动绑定这两个技能、关联企业知识目录、严格校验，完成后收起为「处理完成 > 1分42秒」，给出交付摘要（智能体配置 / 角色定位 / 技能创建与绑定 / 知识库关联）和智能体卡片。点卡片打开右侧配置面板（知识页默认显示关联的企业知识目录）；卡片上「本地测试」另开测试会话，回答前依次显示查询设备档案、查询维修记录、对照经验；「返回主会话」回到创建会话。面板「提交」确认后模拟企业审核通过，面板和卡片状态变为「已发布」。
9. 同一入口说出销售履约的需求和规矩（含“销售履约”“接单”“催收”等词）时，进入「创建销售履约智能体」会话（演示账号林悦，商务主管）：agent-builder 调用 skill-builder 生成并绑定「接单制单」「履约执行」「收款催收」「销售月报」四个技能，经 MCP 连接金蝶 ERP（读客户信用、应收与收款，写销售订单、发货通知、运单、销售出库，写操作先存草稿），关联「销售履约知识库」，交付摘要另列「金蝶 ERP 连接」和待上传的运价表、催收函模板、网页报告模板。本地测试会话提示里可「附上示例采购单」，发送后依次显示解析采购单、查询客户信用、创建销售订单（暂存）、生成网页预览，回答含信用检查表、订单草稿和可点开的订单网页预览，最后询问是否提交审核；提交后模拟企业审核通过，发布给销售团队。

## 工作模式：使用智能体

侧栏顶部切到「工作」时，开发导航和开发视图隐藏，显示工作导航（新任务、定时任务、智能体、技能、发现、历史对话）和对话页；切回「开发」恢复原样。对话页输入框里的智能体选择器可选已发布或已提交的智能体，发送后先显示「深度思考中」，再给出「任务完成 · 调用 N 个技能（经 MCP 读取的系统）」、回答和参考来源（维修记录、内置知识）。「设备故障诊断助手」被问到注塑机温度问题时，先引用维修记录，再按老师傅的经验给出排查步骤；其它智能体和导航项为提示占位，回答均为本地模拟。

## 智能体团队发布规则

- 成员必须引用已发布或待发布的智能体版本，且组长必须是成员。
- 发布时写入成员版本快照；后续成员更新需重新提交智能体团队版本。
- 开发流程的每个阶段展示绑定的智能体，一般 1 位、最多 2 位；未手动绑定时按智能体的「能力项」匹配（阶段看重的能力项 + 成员在这些能力上的等级，第二位须与第一位相当才入选），手动绑定超过 2 位时提示先取消一位；没有任何成员匹配的阶段显示「能力待补齐」。
- 两支内置团队使用固定交付范围：通用应用开发为需求分析、系统设计、开发实现、测试验证；苍穹应用开发为需求分析、开发实现、测试验证（后者阶段描述为空）。具体 WorkItem 由 Runtime 在阶段内动态生成；智能体、技能与业务组件开发属于开发阶段内的工作，不单独增加交付阶段。交付路径只有「功能开发」和「缺陷修复」：需求取团队的交付范围（通用团队需求分析、系统设计、开发实现、测试验证 4 个阶段，苍穹团队 3 个阶段，自建团队默认 4 个阶段），任务类型为「缺陷」的任务无论内置还是自建团队都只有开发实现、测试验证 2 个阶段；不再有「方案咨询」，也没有可选的智能体开发阶段。已缓存的缺陷任务一次性迁移到这 2 个阶段，旧阶段并入相邻阶段并保留状态与产物。
- 能力项一律显示中文名加等级，不出现英文标识；智能体卡片和详情不再展示「可承担的工作」（创建 / 编辑智能体时该字段仍保留）。
- 智能体团队详情的「基本信息」页签只列成员（不再重复展示团队说明和「点名字看定义，星标设组长」提示）；「组长」标记仅在编辑时显示，用于识别和设置组长。
- 智能体团队详情与编辑的「开发流程」页签顶部是路径切换标签（功能开发、缺陷修复，每个标签带阶段数），默认只展示功能开发，点标签切换，每次打开详情都回到功能开发；功能开发显示团队的交付范围，缺陷修复固定显示开发实现、测试验证两个阶段；每条路径的阶段按纵向时间线从上到下排列（左侧圆点加竖线串起各阶段，不显示序号），每个阶段的名称和说明下方展示该阶段绑定的智能体，智能体收在一个带边框的容器里，容器顶部有「AI 智能体执行」标签，说明该阶段由 AI 智能体而不是真人在干活（未绑定智能体时不显示），智能体和「AI 智能体执行」标签在容器里横向排成一行、放不下时换行；居中详情弹窗不显示测试按钮，保存、提交审核和测试仅在对话侧栏的编辑区右上角。
- 下架被已上架智能体团队引用的智能体时，提示引用关系并阻止下架；无真实引用时允许下架，历史版本保留。

## 状态机

草稿 → 待审核 → 已上架 → 已下架；待审核可驳回，驳回回到草稿。已上架产生更新时进入新的草稿/待审核链路，旧上架版本持续可用。

## 用户旅程

个人开发者新增智能体 → 对话生成并编辑 → 提交企业审核 → 租户管理员查看快照并通过/驳回 → 通过后进入更多智能体 → 成员点击“+”安装 → 发现新版本时查看更新说明并整体更新。创建智能体团队时选择成员版本 → 安装团队自动补齐依赖 → 团队固定使用成员快照。

## 原型边界

云端目录、扫描、审核、安装、更新和依赖补齐均为浏览器本地持久化模拟；不代表真实云端分发、包安全扫描或跨设备同步。

## 下拉选择

普通单选字段复用共享下拉组件，统一箭头、面板、选中标记与单边框焦点状态；支持键盘选择、禁用项和空值选项（如「全部」或「无」）。现有搜索、多选选择器保留原有能力，归档页面不迁移。
