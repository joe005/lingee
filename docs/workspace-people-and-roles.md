# 工作区人员与角色

## 首次进入协作开发

- 用户没有可访问的工作区时，协作开发展示创建工作区引导，不展示空的任务或项目页面；通用功能仍可使用。已被创建者或管理员添加到工作区的用户，登录后直接看到可访问的工作区，不提供自助“加入工作区”入口。
- 创建工作区后自动切换至该工作区，并引导创建第一个项目；项目创建后再安排任务。新工作区不自动生成演示项目或任务。当前原型允许已登录用户创建工作区；若正式产品限制创建权限，无权限用户应看到联系管理员的说明。

## 层级与职责

- 工作区级角色只有**成员**和**管理员**。管理员可以维护工作区设置、协作人员关联与角色、系统集成，并创建项目；成员不能创建项目。一个工作区可以有多名管理员，不能移除或降级最后一名管理员。旧本地缓存中的项目经理角色按最小权限迁移为成员，不自动提升为管理员。
- **项目负责人、项目成员**是项目中的身份。新建项目时负责人初始留空，须从工作区所有可用人员中搜索选择；当前用户和选中的负责人自动成为项目成员。管理员或项目负责人可编辑项目资料、添加和移除项目成员，其他人只能查看这些内容。项目详情从工作区人员中按姓名、手机号或邮箱搜索并添加成员，添加后默认为成员。
- 工作区角色和项目负责人身份分别存储。管理员不因其工作区角色自动成为所有项目的成员；项目负责人也不因其项目身份获得整个工作区的设置权限。管理员创建项目后仍须指定具体负责人。
- 项目列表按当前用户提供“我负责的 / 我参与的”视角。“我负责的”指担任项目负责人；“我参与的”指加入了项目但不是负责人。项目列表仍可按工作区筛选。
- 项目列表和卡片只展示字段；有权限的人进入项目详情后编辑。变更项目负责人须展示原负责人和新负责人，确认后才保存，取消时保持原值。

## 人员主数据

灵基维护用户主数据，协作设置只保存灵基用户 ID、用于展示的姓名/手机号/邮箱，以及工作区角色映射；项目通过该 ID 引用协作人员。姓名、手机号和邮箱可用于搜索，但不能作为身份主键。不再提供本地人员导入，也不在协作设置中同步金蝶组织/人员系统。

管理员在设置中添加人员时，按姓名、手机号或邮箱搜索当前租户的灵基用户，从结果中选择后建立协作关联；已关联用户不可重复添加。项目负责人或管理员在项目详情中从已关联的工作区人员里搜索并添加到项目。手机号和邮箱仅用于展示，不能在协作设置中修改。移除操作只解除协作关联，不删除灵基账号；项目负责人、待处理任务或项目唯一成员仍须先处理关联事项。

## 原型与正式接入边界

当前单文件原型的协作映射保存在浏览器，演示角色与项目角色尚未形成服务端权限校验。灵基人员搜索接口尚未提供；原型使用明确标注的演示候选人。正式接入需由服务端按当前租户和调用者权限查询，输入姓名、手机号或邮箱，返回稳定的 `id`、`name`、`phone`、`email`，并对敏感信息展示与搜索权限做控制。搜索适配入口为 `window.cvSearchLingeePeople(query)`；接口路径、鉴权和分页规则待确定。
