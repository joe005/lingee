# 任务

## 目标

让用户从意图创建任务，查看任务清单，按项目和阶段推进执行，并由人员审核产物。

## 入口与视图

- 协作开发 → 任务：按人员分配，默认只展示与当前用户相关的任务：当前阶段由我处理，或我负责的阶段已做完（无执行计划的任务看负责人）；他人负责、我未参与处理的任务不在列表中；项目负责人可通过「负责人 → 全部」筛选查看项目全部任务；阶段评审详情和交付产物按阶段处理权限隔离。可再按“我的任务、待处理”等范围查看。工作区管理员可查看工作区内全部任务。
- 列表页签按“轮到谁”划分：**需要我处理**＝当前阶段由我开始、验收、回答 AI 提问或重试阻塞；**执行中**＝其余未完成任务（AI 执行中，或当前阶段由他人处理）；**已完成**＝任务整体完成，或我负责的阶段已做完（后续阶段由他人处理）。协作开发菜单徽标与“需要我处理”同口径。
- 管理板块项目下新建的研发任务进入同一份任务数据，按阶段执行人分配；管理项目可在项目筛选与新建任务的所属项目中选择，但不出现在协作开发的项目列表。
- 代码分支：项目配置了 Git 仓库和基准分支时，任务详情侧栏显示「代码分支」：`feature/<任务编号>` → 基准分支，状态为待拉取 / 开发中（开始执行时从基准分支拉取）/ 已合并（审核通过、任务完成后合并回基准分支）/ 已关闭。
- 项目卡片 → 任务清单：进入当前项目的全部任务，按最近更新时间倒序。
- 新建任务：直接进入对话，不先要求在弹窗选择项目。

## 关键流程

1. 对话输入框显示 `task-builder` 技能胶囊，在同一位置选择所属项目。
2. 输入任务意图后生成 Markdown 任务建议；用户可补充修改。
3. 选择项目后重新生成建议，点击“确认创建任务”才写入任务。
4. 任务按智能体团队阶段生成执行计划，执行人处理当前阶段并产出交付物。
5. 产物进入待审核；审核通过后流转下一阶段，最终完成任务。
6. 交付智能体的任务（如 T1001506）：开发成果「智能体配置」在任务详情的产物预览里直接打开智能体配置面板（与智能体开发会话同一份，可看角色设定、技能与 MCP、上传知识）。面板里点「提交」弹出「提交上架审核」确认，确认后任务的测试验证与提交上架一并完成，智能体变为「已提交」；验收页按钮为「通过并提交上架」，走同一个确认。
6. 任务详情「…」菜单只提供删除，不提供复制；详情不支持新发评论和子任务，已有评论仍显示在动态里。
7. 只有未开始且未经历任何阶段的任务可删除；已开始或已流转的任务保留执行记录，菜单中“删除”置灰并提示原因，批量删除只处理可删除的任务。
8. 执行计划每个阶段同时显示执行智能体和处理人：智能体按阶段名称从项目绑定的智能体团队中选取；阶段取自团队的交付路径，通用应用开发智能体团队为 5 个阶段：需求分析、架构设计、开发实现、智能体开发、测试验证，其他团队沿用需求分析、方案设计、实现规划、编码实现、测试验证、部署交付。
   - 「智能体开发」阶段开始执行时，直接进入「智能体开发」界面（对话创建智能体、编辑配置、本地 / 云端测试、提交），不走通用任务会话。
   - 通用应用开发团队的「开发实现」产物是部署后的网站：阶段完成或待审核后，阶段下展示「网站预览」，打开后是带地址栏的可操作页面，铺满预览区。页面按项目名和任务标题判断业务主题：问卷类用问卷调研应用，工单类用工单管理系统应用（与应用开发里的工单管理系统同一页面），采购、报销、库存各有对应的演示网站（带侧栏、统计卡片、搜索与状态筛选、详情抽屉、新建），其他主题用任务产物里的演示列表数据；数据和操作只在当前页面生效。
9. 操作记录以任务自带的状态历史为准；历史里已有提交审核、完成或阻塞记录时，不再补推断记录。
10. 任务可指定由单个智能体执行（如「智能体开发」）：执行计划每个阶段都显示该智能体，执行会话、审核报告和任务卡片也以它代替项目的智能体团队。

10. 列表卡片展示状态徽标、编号、项目、标题、一句提示（轮到你开始执行「阶段」／智能体团队已提交「阶段」产物等待确认／AI 正在等你回答／执行受阻原因／当前阶段由某人处理）、任务类型与优先级标签，以及带阶段名称的进度条。右侧按钮随状态变化：交给AI执行、查看并验收产物、回答提问、重新执行、查看详情、查看产物；点击卡片其他区域或标题打开详情。
11. 任务详情：底部主操作与列表同口径，只有轮到当前登录人才出现（交给AI执行／前往确认／回答提问／重新执行）；执行计划每行第一行为阶段名与状态，第二行为执行专家和处理人，当前阶段的同类操作按钮放在行右侧。

## 关键状态

`待交给AI执行` → `执行中` → `待验收` → `已完成`；执行失败进入`已阻塞`，保留旧数据并支持重试或修改。待交给 AI 执行和已阻塞任务在详情底部提供主要操作，分别用于进入 AI 执行会话和重新执行。

## 原型边界

任务和会话使用本地持久化模拟；专家执行、真实通知、服务端并发和审计留给后续实现。
