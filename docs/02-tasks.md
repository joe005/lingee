# 任务

## 目标

让用户从意图创建任务，查看任务清单，按项目和阶段推进执行，并由人员审核产物。

## 入口与视图

- 侧栏「协作开发」的 Beta 标签与任务数量徽标仅作提示，点击菜单文字或徽标均正常进入协作开发，不影响导航与选中态。
- 任务页记住上次选择的看板／列表视图，刷新或重新进入时恢复；项目内任务清单的临时列表不覆盖该偏好。
- 协作开发 → 任务：按人员分配，默认只展示与当前用户相关的任务：当前阶段由我处理，或我负责的阶段已做完（无执行计划的任务看负责人）；他人负责、我未参与处理的任务不在列表中；仅工作区管理员可通过「负责人 → 全部」筛选查看他人任务，普通成员仅可查看自己参与的任务；阶段评审详情和交付产物按阶段处理权限隔离。可再按“我的任务、待处理”等范围查看。工作区管理员可查看工作区内全部任务。
- 列表页签按“轮到谁”划分：**待我处理**＝当前阶段由我开始、验收、回答 AI 提问或重试阻塞；**执行中**＝我所在阶段正在执行（AI 执行中）的任务；**已完成**＝任务整体完成，或我负责的阶段已做完、后续阶段由他人处理（卡片保留任务实际状态）。协作开发菜单徽标与“待我处理”同口径。
- 看板按状态分组时展示「待开始、执行中、待我处理、已完成」：流转到我所在阶段、需要我开始、验收、重试或回复的任务合并到「待我处理」，我所在阶段正在执行的任务归入「执行中」，我的阶段已做完的归入「已完成」；卡片保留实际状态与查看产物／重试／回复按钮（待评审卡片不直接确认，点「查看产物」打开详情，在执行计划里查看产物后再确认）；待评审状态统一显示「待评审」，不把处理人姓名拼入状态名称。该归类不修改任务状态，「待我处理」不接受拖拽改状态。
- 管理板块空间下新建的研发任务进入同一份任务数据，按阶段执行人分配；空间在开发板块按项目展示，可在项目筛选与新建任务的所属项目中选择，但不出现在协作开发的项目列表。
- 代码分支：项目配置了 Git 仓库和基准分支时，任务详情侧栏显示「代码分支」：`feature/<任务编号>` → 基准分支，状态为待拉取 / 开发中（开始执行时从基准分支拉取）/ 已合并（审核通过、任务完成后合并回基准分支）/ 已关闭。
- 项目卡片 → 任务清单：进入当前项目的全部任务，按最近更新时间倒序。
- 新建任务：普通任务页和项目任务清单均保留工具栏「新建」按钮；点击打开新建任务弹窗，默认聚焦可编辑的任务标题输入框，无论是否已选择项目都可直接录入标题；也可切换到智能创建，通过对话整理任务。所属项目、智能体团队、任务类型与优先级沿用统一下拉箭头和选项面板，类型及优先级可用方向键选择、回车确认、Esc 关闭。表单字段名为「所属空间」（原「所属项目」，与 Manage 的空间一致；下拉搜索为「搜索空间」）。所属空间下拉（含智能创建、对话里 task-builder 的项目选择）只列开发空间：有仓库地址的、Manage 里的研发类空间，以及协作开发自己的项目，Manage 的会议、预算等普通空间不列。下拉底部固定「＋ 新建空间」，在 Build 里按 Manage 新建空间的格式填写并粘贴 Git 地址直接新建，建好后自动选中，详见 [03-projects-collaboration.md](03-projects-collaboration.md)「新建空间」。

## 关键流程

- 看板拖拽时卡片以页面浮层跟随指针，原卡片淡化占位，目标栏高亮；成功后平滑落入目标分栏，其他卡片平滑移动填补或让出位置；取消或不允许的落点返回原位置。状态流转限制继续有效，系统开启减少动态效果时跳过归位与移动动画。
- 待开始／待规划任务的看板与列表卡片统一在三个点菜单中提供「编辑」，卡片外仅显示执行相关操作，不重复显示编辑按钮。编辑复用新建任务弹窗，标题为「编辑任务」，带入现有字段和执行计划，保存修改当前任务。
- 列表与看板卡片右侧「查看详情」进入任务会话，优先恢复已有会话；点击标题或卡片其他区域仍打开任务详情。查看会话不改变任务状态。

- 自动阶段完成并启动下一阶段的成功提示显示 3 秒，悬停时暂停计时，可手动关闭。

- 开发阶段关闭人工评审时，阶段完成后自动通过；下一阶段由本人处理时发起新会话、开始执行，提示「上一阶段已完成，开始「下一阶段」」；仅下一阶段处理人为当前用户时自动发起会话；非本人时只流转给该处理人，下一阶段保持待开始，不创建会话，提示「上一阶段已完成，已流转给「姓名」」，显示 3 秒。最后阶段完成则结束整个任务，不再创建会话；开启人工评审时仍等待验收。

- 新建或编辑任务保存后，顶部显示「保存成功」；第一阶段处理人不是当前用户时，显示「保存成功，任务已分配给「姓名」」，姓名取该阶段处理人。保存并启动时，第一阶段由本人处理则复用手动「AI 执行」流程，直接打开新会话并运行，提示「保存成功」，由他人处理则保存并显示分配提示，启动失败保留原因提示。确认删除任务后，单条和批量删除均显示「删除成功」。

- 显示设置中的排序、分组选项支持在面板内滚动，滚动时保持打开；选择选项、点击外部或按 Esc 关闭，外部页面滚动或窗口缩放时关闭浮层以避免定位错位。

点击「保存任务」或「保存并启动」时，一次标红所有未填写的必填项，按任务名、任务描述、所属项目、智能体团队、任务类型的顺序聚焦第一个缺失字段；任务描述必填，纯空格视为未填写，填写有效内容后清除对应错误边框。编辑保存使用相同校验。

新建及编辑任务弹窗的开发阶段表中，执行阶段由智能体团队的交付路径确定，以只读文字展示，不提供下拉选择；评审人保留统一下拉入口，任务已启动后执行人保持禁用。

1. 对话输入框显示 `task-builder` 技能胶囊，在同一位置选择所属项目。
2. 输入任务意图后生成 Markdown 任务建议；用户可补充修改。
3. 选择项目后重新生成建议，点击“确认创建任务”才写入任务。
4. 新建任务的开发阶段里每个节点有「人工评审」开关（默认勾选，可取消），底部有「保存任务」和「保存并启动」两个并排按钮（样式同管理的新建任务，后者保存后立即开始第一阶段，创建人不是第一阶段处理人时只创建并提示）。新建任务时选择智能体团队（项目不绑定团队；默认不选，选完团队才加载执行阶段，任务启动后团队锁定），「任务类型」读自智能体团队详情「开发流程」里的路径（功能开发 / 缺陷修复），选完团队才加载，默认功能开发：功能开发走团队的交付范围，缺陷修复只有开发实现、测试验证，与管理板块一致，执行人处理当前阶段并产出交付物。
5. 产物进入待评审；审核通过后流转下一阶段，最终完成任务。
6. 交付智能体的任务（如 T1001506）：开发成果「智能体配置」在任务详情的产物预览里直接打开智能体配置面板（与智能体开发会话同一份，可看角色设定、技能及其调用的 MCP 工具、上传知识；点「测试」另开测试会话，测完回到协作开发提交）。面板里点「提交」弹出「提交上架审核」确认，确认后任务的测试验证与提交上架一并完成，智能体变为「已提交」；验收页按钮为「通过并提交上架」，走同一个确认。
6. 任务详情「…」菜单只提供删除，不提供复制；详情不支持新发评论和子任务，已有评论仍显示在动态里。
7. 所有状态的任务均可删除，不根据执行阶段、流转记录或状态禁用；单条和批量删除均保留确认流程。已阻塞任务在列表和看板提供「重试」按钮（仅当前阶段处理人可操作）；点击复用已有阻塞会话继续执行，保留失败记录，成功后输出当前阶段的产物卡片并按原流程进入验收。
8. 执行计划每个阶段显示执行智能体（暂不显示处理人，避免被误解为由人执行）：智能体按阶段名称从任务所选的智能体团队中选取；阶段取自团队的交付路径，通用应用开发智能体团队为 4 个阶段：需求分析、系统设计、开发实现、测试验证；苍穹应用开发智能体团队为 3 个阶段：需求分析、开发实现、测试验证。两支内置团队按固定交付范围生成执行计划，阶段内的具体 WorkItem 动态拆分；自建团队保留其配置路径。缓存任务、当前阶段、阶段产物与会话阶段标记同步迁移，保留任务状态和历史。
   - 「智能体开发」阶段开始执行时，直接进入「智能体开发」界面（对话创建智能体、编辑配置、本地 / 云端测试、提交），不走通用任务会话。
   - 通用应用开发团队的「开发实现」产物是部署后的网站：阶段完成或待评审后，阶段下展示「网站预览」，打开后是带地址栏的可操作页面，铺满预览区。页面按项目名和任务标题判断业务主题：问卷类用问卷调研应用，工单类用工单管理系统应用（与应用开发里的工单管理系统同一页面），采购、报销、库存各有对应的演示网站（带侧栏、统计卡片、搜索与状态筛选、详情抽屉、新建），其他主题用任务产物里的演示列表数据；数据和操作只在当前页面生效。
9. 操作记录以任务自带的状态历史为准，不重复补造已有动作；展示范围与文案见「操作记录」。
10. 任务可指定由单个智能体执行（如「智能体开发」）：执行计划每个阶段都显示该智能体，执行会话、审核报告和任务卡片也以它代替任务的智能体团队。

10. 列表卡片展示状态徽标、编号、项目、标题、一句提示（轮到你开始执行「阶段」／智能体团队已提交「阶段」产物等待确认／AI 正在等你回答／执行受阻原因／当前阶段由某人处理）、任务类型与优先级标签，以及带阶段名称的进度条。右侧按钮随状态变化：交给AI执行、评审产物、回答提问、重试、查看详情、查看产物；点击卡片其他区域或标题打开详情。
11. 列表卡片的「评审产物」进入当前阶段的会话详情，与看板的会话入口保持一致，在会话中评审产物。
12. 任务详情：底部主操作与列表同口径，只有轮到当前登录人才出现（交给AI执行／前往确认／回答提问／重试）；执行计划每行第一行为阶段名与状态，第二行为执行智能体（不显示处理人），当前阶段的同类操作按钮放在行右侧；尚未开始的阶段不显示会话。

本地执行前自检：开发项目的任务开始执行前检查当前阶段处理人电脑上的本地环境（Git 账号、项目目录与写权限，见 `03-projects-collaboration.md`「本地开发环境」）。处理人手动点击「AI 执行」时未就绪会进入该项目的智能配置对话（「本地环境配置」技能），配好后点「继续执行任务」接着执行；自动启动（阶段自动流转、Manage「保存并启动」）或由他人触发时不启动，任务转为已阻塞并写明原因，当前阶段处理人在「待我处理」里看到「去配置」，配好后恢复并自动继续执行。

## 关键状态

任务整体完成，或本人负责的阶段已做完且后续阶段由他人处理时，归入个人「已完成」；卡片保留任务实际状态，不将整项任务改为已完成，仍受项目权限与主动筛选限制。

`待交给AI执行` → `执行中` → `待验收` → `已完成`；执行失败进入`已阻塞`，保留旧数据并支持重试或修改。待交给 AI 执行和已阻塞任务在详情底部提供主要操作，分别用于进入 AI 执行会话和重试。

## 原型边界

任务和会话使用本地持久化模拟；智能体执行、真实通知、服务端并发和审计留给后续实现。

## 下拉选择

普通单选字段复用共享下拉组件，统一箭头、面板、选中标记与单边框焦点状态；支持键盘选择、禁用项和空值选项（如「全部」或「无」）。现有搜索、多选选择器保留原有能力，归档页面不迁移。

任务工具栏的「新建」下拉与显示设置面板互斥，打开其中一个时关闭另一个及其子面板。

任务会话的执行阶段区域每次右键直接在 A、B 间切换，不弹出选项菜单：A 为原纵向列表，B 为参考 Ant Design 的无边框横向步骤条（节点与连线），显示阶段、处理人与状态并突出当前阶段；会话拖窄时按内容容器宽度动态压缩列宽与间距，达到最小可读列宽后局部横向滚动，不挤压正文；切到 B 时自动定位当前阶段。默认 A；B 直接显示全部步骤，不显示展开收起入口，切换会话后仍保持平铺；A 保留展开收起交互。仅改变当前页面展示，不修改执行计划。

新建任务填写内容或调整项目、优先级、负责人、执行计划后，点击关闭、取消或按 Esc，显示「放弃更改？」与「关闭后，未保存的内容将丢失。」；默认聚焦「继续编辑」，保留全部输入，「放弃更改」关闭弹窗。未修改直接关闭，成功保存或提交智能创建不触发确认。

顶部操作提示按成功、警告、错误显示对应浅色背景；普通与成功提示默认 3 秒，警告 5 秒，错误 6 秒，长提示最多延长至 8 秒；悬停或聚焦暂停计时，并可手动关闭。

新建任务的「任务类型」读自智能体团队详情「开发流程」里的路径（功能开发 / 缺陷修复），选完团队才加载，默认功能开发，不提供空选项与「方案咨询」；功能开发存为任务类型「需求」、缺陷修复存为「缺陷」；复制或编辑旧任务时，缺陷保留原类型，未设置或旧咨询类型默认显示功能开发。

「新建」下拉仅保留「导入」，下载导入模板入口统一放在导入弹窗内。

协作开发任务嵌入完成或再次进入时立即按当前容器重绘，首次初始化的旧模板不能沿用到现行看板，按钮文案与列表共用当前动作定义。

协作开发任务入口默认展示列表：顶部保留任务、智能体、智能体团队与设置入口，状态页签使用胶囊样式，工具栏直接切换看板／列表；显示设置和新建下拉继续可用。任务卡片展示状态、编号、项目、标题、描述、类型、优先级与阶段进度，按状态提供「AI 执行」「评审产物」「重试」等现有操作；待评审和阻塞卡片的删除按钮复用删除确认，其他状态提供更多菜单。列表使用当前工作区的真实原型数据，数量与阶段数不固定为设计稿示例。

任务卡片的优先级标签直接使用功能配置中的名称，与新建、编辑和筛选选项一致，不追加「优先级」后缀。

任务页显示设置位于顶部导航右侧，与工作区设置入口区分；新建按钮及其下拉箭头统一高度，卡片更多／删除按钮常显，当前阶段名称居中对齐对应节点。

任务列表卡片已有「AI 执行」主按钮时，更多菜单不再重复提供「开始执行／发起会话」，保留删除操作，不提供复制。

最新版任务详情以任务概况、执行计划和操作记录分区展示，默认侧滑宽度 640px，保留宽度调整、字段编辑、附件、会话与产物操作；未开始任务也显示实际执行计划。新建任务弹窗为一页式，版式与管理的新建研发任务一致：任务标题、任务描述通栏，下方圆角卡片内是所属项目、智能体团队、任务类型、优先级两列排列和「开发阶段」表（序号、执行阶段、智能体、人工评审、评审人，阶段不能增删）；底部为取消、保存任务、保存并启动。属性区第一行是所属项目与智能体团队，第二行是任务类型与优先级；优先级，可选紧急、高、中、低，新建默认「中」，编辑时带出原值并可修改。现有校验、智能创建和未保存关闭确认继续有效。

任务列表与看板的次要操作统一使用三个点下拉入口；待规划／待开始且从未执行、未流转的任务显示「编辑」与「删除」，编辑复用任务编辑弹窗，其他任务不显示编辑；再次点击同一按钮、点击菜单外部或按 Esc 收起菜单，Esc 将焦点返回触发按钮；菜单位置限制在可视窗口内。待评审和阻塞卡片即使只有删除操作，也在菜单内展示，删除菜单项支持键盘聚焦，沿用删除权限与确认流程。

协作开发任务看板采用圆角分栏与卡片，卡片依次显示状态、编号与项目、标题、描述、类型和实际优先级，底部显示当前执行阶段与对应操作。开始、验收、重试、回复及查看产物沿用任务权限和流程；更多操作统一使用三个点入口，保留分组折叠、子任务展开与拖拽。按状态分组依次为待我处理、执行中、已完成；待开始和待规划并入待我处理，卡片保留实际状态。

任务卡片更多菜单点击菜单外区域（包括页面空白）时关闭，菜单内操作保持正常触发。

新建任务的开发阶段使用「人工评审」开关，默认节点和新增节点默认勾选；勾选保存为需要人工确认，取消勾选保存为无需人工确认，阶段完成后沿用自动审核并继续下一阶段的流程。编辑既有计划保留已保存的审核设置。

执行计划中未选择执行人的控件显示为空并保留下拉箭头，不展示「待分配」占位文字；点击仍可选择项目成员。

看板卡片的三个点位于右上角，悬停或键盘聚焦卡片时展示；触摸设备常显。列表卡片仍保持原位置和常显方式。

看板与列表中待评审任务统一显示「评审产物」按钮，点击打开对应阶段的会话详情，优先恢复已有会话，与任务详情底部入口一致；最终确认仍遵守阶段审核权限。

协作开发看板卡片始终展示已有任务描述，位于标题下方，单行超长省略，悬停可查看完整文字；不受旧版卡片描述隐藏偏好的影响。

新建任务底部提供主按钮「保存并启动」，通过现有表单与执行人校验后创建任务并复用任务启动流程；「保存任务」为次要按钮，仅创建草案。编辑已有任务仍只保存修改，启动权限沿用当前阶段处理人规则。

新建任务的开发阶段里，执行阶段为只读文字（取自所选团队的交付阶段），每个阶段下的智能体随阶段匹配并单独一列展示；评审人选择与人工评审开关可用；阶段随团队和任务类型固定，不能添加或移除节点。

导航徽标与当前任务页「待我处理」数量同步：看板复用该状态分组计数，列表复用待处理页签计数，包含待开始任务并随任务变化刷新。

任务页看板／列表选项在当前浏览器本地缓存，刷新及重新进入任务入口恢复上次选择，不再强制重置为列表；项目内列表不会覆盖任务页视图偏好。

产物评审的「继续修改」显示在「通过评审」左侧，仅当前阶段处理人可操作；点击退回当前阶段后进入任务已有会话，优先复用当前阶段会话，不重复登记修改会话。只读查看产物时隐藏两个评审按钮。

看板和列表读取同一任务数据源并共用看板状态分组口径：待我处理、执行中、已完成。列表页签计数、列表内容和导航徽标均复用分组结果；看板顶部提供任务标题、编号和描述搜索，无匹配时显示提示；切换展示方式保留筛选与搜索，不改变任务集合，新增、修改、删除同步反映到两个视图。

**空间切换（统一过滤）**：工具栏左侧「全部空间 ▾」，列表和看板共用，选一个空间后列表、看板、页签计数和协作开发徽标都只算该空间的任务。下拉带搜索，第一项「全部空间」，其后列开发空间和当前条件下有任务的空间，右侧显示任务数，已选的排在最前、打勾。与「筛选」里的「空间」（原「项目」）是同一份条件：在下拉里选是单选替换；在筛选里多选时按钮显示「N 个空间」；重置筛选即回到全部空间。选择随视图状态保存。项目任务清单里空间已固定，不显示该按钮。列表字段「项目」改称「空间」。

看板与列表共用状态按钮配置及点击处理：AI 执行、评审产物、重试、回复、查看产物和查看详情，两种展示的文案、入口与权限行为一致。

看板所有状态的任务卡片点击均打开任务详情；卡片内操作按钮独立处理执行、会话或产物操作，避免点击卡片直接进入会话。Ctrl / Command 点击继续用于多选。

当前任务详情的「任务概况」不展示或编辑标签字段，保留状态、项目、优先级和任务描述。

协作开发任务页在工具栏显示「显示设置」齿轮入口，视图切换使用工具栏中的看板／列表按钮。

任务详情操作集中在底部，待评审任务显示「评审产物」主按钮，点击打开对应阶段会话详情，优先恢复已有会话；进入会话不改变任务状态，实际确认仍遵守阶段处理人权限。

任务详情执行计划按时间线展示：每张阶段卡片首行为执行智能体、处理人姓名，状态靠右；第二行为阶段名称，需人工确认时不显示评审标签，自动审核时显示「自动评审」，以阶段的人工评审配置为准。阶段内不显示操作按钮和会话信息，待评审与已完成阶段的产物直接显示为文件列表，点击可预览；详情底部删除靠左，未开始且未流转任务显示编辑，主操作靠右（待开始为「AI 执行」，待评审为「评审产物」）。删除沿用所有状态可删除的规则和确认流程。

任务看板卡片与列表中的任务类型文案使用智能体团队开发流程的实际选项（功能开发 / 缺陷修复），存储值继续使用需求 / 缺陷。
模拟数据与本地缓存任务缺少任务类型时统一补全：缺陷任务补为缺陷，其余补为需求；已有类型保留，后续补种和新增任务执行相同规则。

执行中任务在看板与列表的「查看详情」按钮进入当前执行会话；点击卡片主体仍打开任务详情。

新建任务默认带出当前账号上次成功创建任务的项目和智能体团队；从项目入口新建时优先使用当前项目。失效或无权限的项目、已删除的团队不带出。任务类型每次默认需求（显示为功能开发），取消创建及编辑既有任务不更新记忆。
任务页支持新建快捷键：macOS 使用 ⌘N，其他系统使用 Ctrl+N，悬停「新建任务」显示对应提示。弹窗打开后重复按键不重置表单，离开任务页不触发。

开发板块新建任务底部按钮使用「保存」与「保存并启动」文案，保存行为不变。

任务看板与列表无结果时统一显示「暂无数据」，空状态不提供清除筛选按钮。

待回答任务中，当前阶段处理人或拥有待回答会话的账号看到「回复问题」，点击进入对应会话；其他可查看任务的账号显示「查看会话」。

执行中任务的看板与列表操作按钮显示「查看会话」，点击进入执行会话。

新建任务弹窗点击蒙版区域不关闭，也不触发放弃更改确认；通过关闭按钮、取消或 Esc 退出。

已完成的「客服工单查询与验收」演示任务按所属内置团队展示完整交付阶段，全部标记已完成；旧缓存的单阶段样本自动补齐，原产物同步归入测试验证阶段。

智能创建的项目与团队选择沿用苍穹开发关联应用控件视觉，提示项不作为选项；对话可指定或修改紧急、高、中、低优先级，推荐任务展示实际优先级，确认后按该值保存，未指定默认为中。

任务看板／列表切换使用灰色底槽与白色滑块的分段控件，保留图标和文字，选中项加深加粗；滑块移动 180ms、内容淡入 120ms，支持左右方向键及 Home／End 切换，减少动态效果时关闭动画，继续保留搜索、筛选与视图记忆。

任务会话执行阶段名称旁仅在自动审核时显示「自动评审」标签，人工评审不显示标签。两种模式均保留「评审人 姓名」，该人员也是阶段执行处理人，阶段流转交给他执行；审核方式与执行状态分别展示。

## 操作记录

入口：任务详情的「操作记录」，以及会话右侧打开的任务详情。记录创建、阶段执行与评审的关键动作，操作人与阶段明确对应。

操作记录可展开或折叠；每个任务的折叠状态保存在当前浏览器，重新打开任务或刷新页面后保留。点击折叠时保持详情当前滚动位置。

| 场景 | 示例 |
| --- | --- |
| 创建任务 | 吴晓锋 创建了这个任务 |
| 创建并启动 | 吴晓锋 创建并启动了这个任务 |
| 开始执行阶段 | 吴晓锋 开始执行「需求分析」 |
| 开始下一阶段 | 张利军 开始执行「开发实现」 |
| 提交评审／再次提交 | 苍穹产品智能体「需求分析」执行完成，提交评审 |
| 人工评审通过并流转 | 吴晓锋「需求分析」评审通过，流转至「开发实现」 |
| 无需人工评审，完成并流转 | 苍穹元数据智能体「开发实现」执行完成，流转至「测试验证」 |
| 人工确认任务完成 | 陈瑾「测试验证」评审通过，任务已完成 |
| 无需人工评审，任务完成 | 苍穹测试智能体「测试验证」执行完成，任务已完成 |

- 创建与创建并启动二选一；保存并启动成功时不重复展示首次开始执行，只保存或无法启动时显示创建记录。创建时间取任务实际创建时间。
- 开始执行由实际操作人员署名；提交评审及无需人工评审的完成记录由阶段实际执行智能体署名，未记录实际执行者时取该阶段首个有效候选智能体；人工评审由实际操作人员署名，不把候选智能体名单作为共同操作人。
- 无需人工评审的阶段只展示「执行完成，流转至下一阶段／任务已完成」，不另展示提交评审；新记录合并保存，预制任务与所有旧缓存兼容去重。需要人工评审时保留提交评审与人工确认两条记录。阶段通过与流转合并为一条记录；最后阶段通过后记录任务完成。无需人工评审的文案使用「执行完成」，旧「已自动通过」记录同步使用此文案。
- 自己开发、自己确认产物；会话底部点击「确认／完成」后追加阶段记录，已打开的右侧任务详情即时刷新，不展示人工评审未通过记录。
- 时间统一展示到分钟，例如 `2026-10-12 17:30`；新记录保留秒级原始时间，旧记录保留原精度，排序兼容两种格式并尊重历史保存顺序。
- 不展示取消任务、通用状态调整、分配处理人、手动流转、阻塞、恢复执行和系统重试说明；任务状态与重试能力仍按现有流程保留。普通评论单独展示，字段修改与附件增删暂不生成专门操作记录。
- 预制任务按现有执行计划补齐演示历史，兼容旧缓存并修正已知预制记录的阶段与署名，清理重复启动和旧审核流转备注；保留用户实际操作，不修改任务状态和执行计划，用户新建任务不补造演示历史。

执行计划当前阶段等待会话问题回答时显示「待回答」，与底部「回复问题」一致。操作记录过滤旧分配处理人、手动流转与通用状态备注；预制历史按当前阶段审核方式展示，自动审核不展示提交评审，并由执行智能体署名完成记录，用户实际人工评审记录保留原事实。

任务详情执行阶段区域外层标题统一为「执行计划」，卡片内不重复显示同名标题，保留团队信息、阶段时间线与产物列表。

任务会话横向阶段样式保留横向节点与连线，显示阶段名称、审核方式、评审人与状态；窄窗口达到最小可读宽度后局部横向滚动，不改为纵向排列。

看板任务描述默认隐藏，按显示设置中的「描述」开关展示，保留用户已保存的显示偏好；列表描述展示不受此调整影响。

看板卡片的任务类型与优先级默认隐藏，显示设置可分别开启；已有显示配置一次性迁移为隐藏，之后保留用户选择。全部附加属性隐藏时不保留空白属性行，列表字段展示不受此调整影响。

会话横向步骤条的审核方式独立一行，使用次要文字，不与阶段标题挤在同一行；顺序为阶段标记、阶段名称、审核方式、状态、评审人。

任务列表与看板隐藏工具栏通用「筛选」按钮，保留搜索和看板「已完成」栏的完成类型筛选；已有筛选条件与数据逻辑保留。

任务详情编辑与删除恢复到右上角关闭按钮左侧的三点菜单，不再在底部展示；未开始且未流转任务可编辑，删除沿用确认流程，底部保留任务主操作，详情保留右上角关闭按钮，也可通过 Esc 或点击外部关闭。

本人阶段已完成且流转给他人的任务保留在个人「已完成」分组，列表与看板显示绿色「阶段完成」标签；该标签仅表示本人阶段已交付，不改变任务整体状态与操作权限。

整项任务已完成时，列表与看板均显示绿色「已完成」标签；本人阶段完成并流转给他人时显示绿色「阶段完成」，两者保持区分。

看板按状态分组时，「已完成」栏右上角使用共享下拉组件提供完成类型筛选，默认「全部」，选项依次为「全部」「阶段完成」（本人阶段完成并流转给他人）和「全部完成」（整项任务完成）；仅影响该栏卡片与数量，不改变其他分栏和列表筛选，无匹配时显示「暂无数据」。

当前阶段仅由本人处理时显示「AI 执行」「评审产物」「重试／去配置」「回复问题」等操作入口，并在点击时再次校验处理人；本人阶段完成并流转给他人的任务只提供查看入口，详情底部不显示阶段处理按钮，卡片保留绿色「阶段完成」标记。

本人阶段已完成并流转给他人的任务与整项已完成任务均显示「查看产物」，点击查看任务产物；其他打开会话的次要按钮显示「查看会话」，点击任务标题或卡片主体打开任务详情。

「查看产物」「评审产物」恢复为右侧产物预览面板：左侧交付产物列表、右侧文件信息与正文，支持切换文件和关闭返回。查看产物展示已完成阶段产物并只读；评审产物展示当前待评审阶段产物，仅当前阶段处理人可确认，入口不再跳转会话。

产物预览标题区仅显示任务标题与关闭按钮，不显示「待评审产物」和任务编号／项目／阶段／产物数量信息行；标题区收紧为单行布局。普通评审确认按钮为「通过评审」，智能体提交上架场景保留「通过并提交上架」。

任务列表／看板切换按钮只展示图标，隐藏可见文字，保留悬停提示与无障碍名称，切换与键盘行为不变。

吴晓锋预制任务补充 T1001212（本人需求分析阶段执行中）与 T1001213（本人需求分析阶段待回复），分别覆盖「执行中」与「待我处理」；旧样本已流转给他人时仍归入「阶段完成」，补种仅添加缺失样本，不覆盖已有回复或任务进度。
