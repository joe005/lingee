01

整体方案

Solution

以灵基Build 协同开发标品为基础、任务为核心驱动：需求进来即创建任务，按阶段执行、上报产物并继续流转，形成研发小闭环。AI OPS 负责需求入口与任务界面等前台，Build 聚焦后台，复用标品能力完成任务持久化与执行。

原则 01

标品为基础

复用 Build 标品的任务、智能体团队与技能能力，不做两套页面。

原则 02

任务为核心驱动

AI OPS 下发需求并使用任务界面，Build 负责任务持久化与执行。

原则 03

状态与成果闭环

运行完成后状态同步回 AI OPS，阶段产物经 API 获取后上报。

标品复用与差异

本次融合以标品为基础，下表列出与标品的差异点及需要改进的地方。

能力复用的标品能力差异与需改进类型
任务任务驱动研发流程任务界面由 AI OPS 使用，Build 只做持久化；需求由 AI OPS 下发，运行完成后状态同步回去；新增任务创建、状态查询 API 与主动推送改进
智能体团队智能体团队编排研发流程适配 DevOps 复杂流程，评审可配置自动通过，补充阶段通知；支持新建智能体团队改进
智能体与技能技能组装智能体云端维护、本地招募或安装；多个智能体复用同一技能；支持新建智能体改进
工作区—新增 Build 工作区能力与同步，支撑 Git 多仓库新增
产物阶段产出成果后端提供产物获取 API，AI OPS 获取后区分文档与代码上报改进
过渡策略先按现有机制跑通：交付沿用 Git，linky CLI 通道短期保留；产物由 AI OPS 通过 API 从 Build 后端获取并上报到工作项文件服务器；推送和多仓库就绪后再逐步替换。
