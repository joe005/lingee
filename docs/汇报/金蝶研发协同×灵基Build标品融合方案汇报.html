01

背景与目标

Background

AI 时代由智能体团队按固化流程自驱动研发，双方已对齐这一理念。

问题 01

两套入口、两套页面

重复开发，独立代码库长期成本高。

问题 02

任务流转断点

从故事 / 缺陷直接跳会话，缺少承接和状态回传。

问题 03

实时性不足

客户端轮询导致推送延迟，产物上传慢、无提示。

目标一个入口、一套能力、一条任务链路。
02

融合总体方案

Architecture

融合原则是「一个入口、不做两套页面」：研发协同做成标品，项目管理等按金蝶定制，核心 AI 研发能力复用同一套前后端。

金蝶侧只产生任务并归集产物；任务透传到 Build 后由智能体团队按研发流程执行，每完成一个阶段就回传状态。

03

核心能力对齐

Capabilities

任务和产物是本次对接重点，其余能力直接用标品。

能力要点定位
任务通用载体（故事 / 缺陷 / 专题规划），不做列表页，透传落库对接重点
技能 → 智能体统一归集、组装；下发到个人 / 团队 / 工作区复用标品
智能体团队即研发模式编排；按产品线配置，流程云端同步复用标品
产物中心按标识映射上传，金蝶侧只做归集对接重点
