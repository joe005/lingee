# 任务会话「执行阶段」原型与代码对照

- 日期：2026-11-24
- 范围：协作开发任务打开的会话，包括顶部执行阶段卡片、底部确认条、确认后的流转、下一阶段衔接
- 代码基准：`lingee-build` feature_dev 分支 `0129cc29b4`（本机工作区，只读，静态阅读源码，未运行）
- 原型基准：`main` 分支当前工作区

## 结论

主流程一致：都有执行阶段卡片和「「X」已完成，请确认产物」确认条；人工评审阶段确认后，下一阶段都停在「待开始」，不自动执行。
差异集中在四处：阶段卡片的展示方式和状态名、确认条由谁可见、确认后会话底部的样子、开发阶段确认时的代码提交过程。原型比代码多出的部分（横向步骤条、自动评审标签、待回答状态）需要先决定是推动代码补上，还是从原型里去掉。

## 逐项对照

### 1. 顶部执行阶段卡片

| 项目 | 原型 | 代码 | 判断 |
|---|---|---|---|
| 位置与折叠 | 会话顶部，标题「执行阶段」+ 当前阶段名 + 序号/总数，可展开 | 相同（`execution-stage-card.tsx`） | 一致 |
| 横向步骤条 | 右键在纵向列表 A 与横向步骤条 B 之间切换 | 只有纵向列表，没有横向样式 | **原型多出** |
| 「自动评审」标签 | 自动评审的阶段显示标签 | 不显示 | **原型多出** |
| 执行中的状态名 | 「执行中」 | 「进行中」 | **文案不同** |
| 等待回答 | 阶段显示「待回答」 | 会话卡片显示「进行中」；「待回复」只用在任务看板 | **原型多出，看板与会话口径也不同** |
| 待开始 / 未开始 | 只有待规划任务的当前阶段显示「待开始」，其余「未开始」 | 后端可立即启动的显示「待开始」，否则「未开始」 | 规则不同，结果多数相同 |
| 已取消 | 没有 | 有「已取消」 | **代码多出** |
| 「评审人」取谁 | 当前阶段取当前处理人，其余取阶段处理人 | 取阶段的指定评审人；自动评审阶段取执行人 | 名字通常相同，口径不同 |

### 2. 底部确认条

| 项目 | 原型 | 代码 | 判断 |
|---|---|---|---|
| 文案 | 「「X」已完成，请确认产物。」「确认后流转至「Y」。」 | 相同 | 一致 |
| 最后一个阶段 | 第二行「确认后任务完成。」，按钮「完成」 | 不显示第二行，按钮仍是「确认」 | **不同** |
| 谁能看到 | 只看任务状态，打开会话的人都能看到 | 只有指定评审人或项目负责人看到 | **不同，原型缺权限判断** |
| 何时出现 | 本轮回复结束、任务进入待评审 | 会话不再产出（包括子智能体也跑完）、评审已开启 | 一致 |
| 确认弹窗 | 标题「确认产物」，「通过后进入「Y」，**处理人**：Z。」/「通过后任务完成。」 | 「通过后进入「Y」，**评审人**：Z。」/「通过后本任务的全部阶段完成。」 | **文案不同** |
| 别处已处理 | 无 | 点确认前重新查一次，已处理时提示「该阶段已在别处处理过」 | **代码多出** |

### 3. 开发阶段确认时的代码提交

| 项目 | 原型 | 代码 | 判断 |
|---|---|---|---|
| 提交方式 | 模拟「检查并合并本轮分支」，弹窗多一句合并说明 | 本机 Agent 执行 Git 提交与推送（封存），等结果后才算流转成功 | **过程不同** |
| 本机没装 Git | 不检查 | 本阶段执行人是自己时先检查 Git，没装就弹「安装 Git」引导，装好后「重新检测」 | **代码多出** |
| 提交慢或失败 | 无 | 提示「仍在提交」或「提交失败」及原因，提示不自动消失 | **代码多出** |
| 测试阶段 | 最后一个测试阶段的弹窗提示「测试报告将自动关联审核记录」 | 无此提示 | **原型多出** |

### 4. 确认之后

| 项目 | 原型 | 代码 | 判断 |
|---|---|---|---|
| 会话里的结束标记 | 在最后一条回复下方插入「「X」已完成」，输入框隐藏 | 输入框位置换成「「X」已完成」页脚，刷新后仍在 | **位置不同** |
| 成功提示 | 「流转成功」；最后阶段「任务完成」 | 一律「流转成功」 | 小差异 |
| 人工评审阶段的下一阶段 | 待开始，不自动执行 | 相同：停在当前会话，由用户决定何时开始 | 一致 |
| 自动评审、下一阶段是我 | 新建会话并执行，提示「上一阶段已完成，开始「Y」」 | 会话页开着时自动跳到新会话，提示「已自动开始「Y」」；关掉页面也会由本机 Agent 继续执行 | **提示文案不同** |
| 自动评审、下一阶段是别人 | 提示「上一阶段已完成，已流转给「姓名」」 | 会话页没有对应提示 | **原型多出** |

## 建议处理

需要你拍板的分两类：

1. **以代码为准，改原型**（代码是有意为之，原型只是没跟上）：执行中的状态名、确认条只对评审人和项目负责人显示、最后阶段的按钮和文案、确认弹窗「评审人」、确认后的完成页脚、自动开始的提示文案、开发阶段的 Git 检查与提交中提示、「已取消」状态。
   - 2026-11-24 已改原型。代码提交「仍在提交／提交失败」的提示没有补：原型的开发阶段仍走模拟合并流程，合并成功的提示也与任务详情共用，没有改。
2. **原型多出，需决定保留还是删掉**：保留就要写成需求交给研发，删掉就从原型和 `docs/02-tasks.md` 里一起去掉。
   - 横向步骤条（右键切换）
   - 「自动评审」标签
   - 会话卡片的「待回答」状态
   - 下一阶段由别人处理时的「已流转给某人」提示
   - 测试阶段的「测试报告自动关联」提示

## 去留结论（2026-11-24）

- 保留，交研发实现：「自动评审」标签、会话卡片的「待回复」状态、自动评审后流转给他人的提示。原型已保留，「待回答」在会话卡片上改为「待回复」，与客户端任务看板一致。
- 已从原型和 `docs/02-tasks.md` 删除：右键切换横向步骤条、测试阶段「测试报告将自动关联审核记录」提示。

作为执行任务阶段的成员，我希望在任务会话里看清每个阶段是否需要人工评审、AI 是否在等我回答，以及阶段自动完成后交给了谁，以便不用切回任务看板就知道下一步。

## 范围

1. 现状：会话顶部执行阶段卡片只显示阶段名、评审人和状态，AI 等待回答时仍显示「进行中」，自动评审完成并流转给他人时会话里没有提示；

## 入口与权限

1. 入口：开发 > 协作开发 > 任务，打开任务的执行会话；
2. 权限：能打开该会话的成员都能看到，不新增操作。

## 功能规则

1. 自动评审的阶段（未开启人工评审）在阶段名称旁显示「自动评审」标签，人工评审的阶段不显示标签；
2. 当前阶段的 AI 在等待用户回答时，阶段状态显示「待回复」，与任务看板用词一致，回答后恢复「进行中」；
3. 自动评审的阶段完成后，下一阶段由其他成员处理时，会话里提示「「阶段」已完成，已流转给「姓名」」，显示 3 秒；下一阶段是自己时沿用现有「已自动开始「阶段」」并进入新会话。

## 原型

验收标准（填「验收标准」字段）：

1. 打开含自动评审阶段的任务会话，展开执行阶段 → 该阶段名称旁有「自动评审」，人工评审阶段没有；
