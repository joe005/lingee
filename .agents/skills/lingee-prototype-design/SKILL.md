# Lingee 原型界面设计

让修改后的界面融入当前原型，信息层级清楚、操作一致，并落实到对应页面源码。用户明确指定的设计、截图或参考优先；不因使用本 skill 扩大改动范围。

## 先确定依据

以下源码路径均相对于项目根目录。

1. 阅读根目录 `AGENTS.md`、`README.md` 中的源码结构与注意事项，检查工作区已有改动。
2. 找到目标页面的 HTML、CSS、JS 和弹窗，并选一个当前在用的同类页面对照。用户指定参考时先比较参考与现状，再决定复用内容。
3. 阅读 `src/styles/tokens.css` 和目标页实际使用的共享样式，查看 `src/styles/app.css` 的层叠顺序。不要只凭组件预览或旧截图推断实际样式。
4. Wiki 存在时按 `AGENTS.md` 的入口与映射查阅；缺失时直接查源码，不编造文档结论，也不为此生成 Wiki。

按任务选读，不必每次加载所有来源：

| 问题 | 源码依据 |
| --- | --- |
| 配色、语义色、阴影、已有尺寸令牌 | `src/styles/tokens.css` |
| 列表标题、操作区、视图页签 | `src/styles/parts/shared-list-page.css`，核对 `.list-page-*` 的调用 |
| 协作页面容器、导航、表格 | `src/styles/parts/collab/` 下的 `08-shared-layout.css`、`11-shared-navigation.css`、`15-shared-tables.css` |
| 项目列表、详情、编辑表单 | `src/views/collab/projects.html`、`src/modals/collab/projects.html`；`src/styles/parts/collab/` 下的 `16-projects-list.css`、`18-projects-detail.css`、`20-projects-editor.css` |
| 控件种类和组合示例 | `src/views/design.html`、`src/scripts/features/design/components.js`；示例有历史内联样式，不直接复制硬编码值 |
| 图标 | `src/assets/icons/README.md` 和对应 SVG，沿用页面现有内联 SVG 方式 |

依据顺序：用户当前明确要求 → 目标页当前实现及共享组件 → 设计系统示例。视觉令牌以 `tokens.css` 为唯一来源；新视觉值尚不存在时新增有明确用途的令牌，不擅自改全局品牌色。

## 布局

- 延续现有浅色企业工作界面：清晰的标题与内容层级、紧凑且可读的信息密度、克制的分隔和留白。除非用户明确要求，不引入营销大标题、装饰渐变或整页卡片套卡片。
- 列表页优先复用现有标题区和页签结构：标题与数量在左，搜索和主操作在右；筛选、视图切换与内容区对齐。同一操作区突出一个主要动作，低频动作放入现有更多菜单。
- 列表用于扫描和比较，卡片用于独立对象摘要；依据任务和同类页面选择，不为视觉变化强行更换载体。
- 详情页让对象标题、状态与主要操作易于定位；沿用目标页已有的分栏或页签，避免增加重复导航。
- 先检查容器已承担的 padding、gap、宽度与滚动责任，避免子页叠加缩进或出现双重滚动。复用既有尺寸；新增间距优先从 4、8、12、16、24px 中选与相邻区域一致的值，不批量改旧页面。
- 对长名称、多成员、无数据和窄窗口安排换行、截断或局部滚动；flex/grid 子项按需使用 `min-width:0`、`min-height:0`。表格溢出由内容区承接，不挤出整页。

## 控件与状态

- 优先复用同类页面已有按钮、输入框、选择器、标签、菜单和弹窗结构及行为。不要为局部调整引入新的 UI 框架或全局组件体系。
- 单选、多选、开关分别表达互斥选项、集合选择和即时开关；对象较多时沿用可搜索选择器。按钮文案使用明确动作，图标按钮提供可访问名称和必要提示。
- 表单字段有常显标签，placeholder 只作示例或提示；必填、帮助和错误信息靠近字段。同一行控件高度、基线、间距一致，沿用目标页面的密度。
- 编辑弹窗延续已有标题、内容、底部操作分区；长内容在主体滚动，主要操作保持可达，宽高不超出窗口。关闭、取消、Esc 与焦点返回沿用现有约定，保护尚未保存的输入。
- 为本次涉及的控件落实适用状态：默认、悬停、键盘焦点、选中、禁用、加载；列表和表单处理适用的空态、无结果、失败与成功反馈。不为无异步行为的控件虚构加载流程。
- 状态不能只靠颜色区分，配合文字或图标；保留清晰的 `focus-visible`，优先使用原生 button/input/select 语义。展示为可操作的控件必须接入实际行为，暂不可用时明确禁用原因。

## 样式

- 使用语义变量：品牌 `--brand`/`--brand-fill`，正文 `--text`，辅助文字 `--text-secondary`，背景 `--bg`/`--fill-1`，描边 `--border`，反馈 `--success`/`--warning`/`--danger` 及对应背景。按含义选取，不借用不相关业务令牌凑颜色。
- 字体继承当前页面；标题、正文、辅助信息的字号与字重沿用现有层级。颜色、字号、圆角、阴影需要新增或变更值时，在 `tokens.css` 中维护有明确用途的变量，再由目标样式引用；不要为了统一局部控件改动影响其他页面的全局变量。
- 图标延续已有 SVG 的尺寸、线宽、对齐和 `currentColor` 用法，不混用 emoji 作为普通操作图标。头像与业务图片沿用真实数据字段及现有回退机制。
- 边框用于分区，阴影用于表达浮层；控制装饰强度。修改放在对应页面 CSS，限定页面作用域，避免裸 `button`、`input` 等全局选择器和不断叠加 `!important`。

## 落地与核对

开始实现前，用简短说明交代本次布局、复用控件及样式依据；小改动一句即可，不要求额外设计文档或等待确认。

遵守 `AGENTS.md` 的文件归属、归档保护、初始化与共享状态约定。保留既有 CSS 导入相对顺序、DOM id 和路由契约。共享样式变更先查调用范围；局部需求优先局部实现。日常设计修改不更新变更日志。

完成后：

- 对照本次要求检查布局层级、控件行为、适用状态、视觉令牌与样式作用域，排除对无关页面的覆盖。
- 按项目要求依次运行 `npm run check`、`npm run build`，并执行 `git diff --check`。
- 默认不启动浏览器。只有当前任务明确要求浏览器验证才执行；否则交付时明确为静态与构建验证，视觉和页面操作效果尚未经浏览器验证。
- 说明改动与验证结论，遇到既有错误区分其与本次修改的关系，不把构建成功当作视觉验收通过。
